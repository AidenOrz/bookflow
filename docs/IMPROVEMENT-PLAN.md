# bookflow 改进计划

> 输入：`2026-11-13 工作流缺陷分析`（外部审阅意见）。该文提出 16 条建议，
> 本计划核实其中 **12 条**（§5.2 的双栏/表格/公式属架构边界外，见 `docs/architecture.md` 第 1 节，不排期）。
> 方式：**逐条核实**后再排期——审阅意见基于只读审阅，部分结论与代码现状不符。
> 核实手段：读全量源码 + 做可复现探针（不改项目文件）+ 三本真书产物实测。
> 基线：35 个测试用例全过；三本成书 `book.md` 逐字节可复现。

## 0. 一句话结论

审阅意见的**方向判断是对的**（工程基建跟不上算法复杂度、存在断链环节），
但逐条核实后：**7 条完全成立**、**2 条被实测证伪**（跨页缩进优先、阈值外部化）、
**2 条表述有误需修正口径**（elen 是 2 个口径不是 3 个；logging 只需改 12 处不是 75 处）、
**1 条成立但修法要改**（脚注弹窗率：主推的两条技术路线实测无效）。

更重要的是：审阅意见**漏掉了两个更严重的问题**——
`fix.py` 已经**把成书里 3 处正确原文改错**（§2.1），
`ocr_layout` 会**静默反压** `ocr_merged` 丢弃全部裁决成果（§2.2）。

本计划据此重排为 **P0/P1/P2 + 明确不做**。

## 2. 两个审阅意见漏掉的、更严重的问题

### 2.1 【已落盘】`fix.py` 已把成书里 3 处正确原文改错

这不是"潜在风险"，是**已经在 `run-guixun/out/book.md` 里**、可直接 grep 的事实：

| 原书正确写法 | 成书里的样子 | 触发规则 | 复核命令 |
|---|---|---|---|
| 引人**入**胜 | 引**入人**胜 | `fix.py:40` 排除表不含「人胜」 | `grep 引入人胜 run-guixun/out/book.md` → 1 |
| 不引人怀疑 | 不引**入**怀疑 | `fix.py:40` 排除表不含「怀疑」 | 同上 → 1 |
| 税收人说 | 税收**入**说 | `fix.py:43` 排除表不含「说」 | 同上 → 1 |

上下文：「那本**引人入胜**的小册子《论自由》」→「引入人胜」；
「因而不留痕迹，**不引人怀疑**」→「不引入怀疑」；
「一家企业的**税收人说**」→「税收入说」。

三处都是**造出了中文里根本不存在的词**，比漏改更糟——读者一眼能看到。
根因：`引人`/`收人` 属「单字替换 + 有限排除表」，而中文「X+人+动词」是**开放集**，
任何有限排除表都堵不住。实测三本书 CTX_RULES 命中 81 处，至少 3 处错 = **误改率 4.2%**；
保留组（整词级替换）三本 **0 处误改**。

### 2.2 【潜在】`ocr_layout` 反压 `ocr_merged`，且 layout 阶段自反馈

`bookflow.py:97-99` 的注释写着「`ocr_merged` … 必须排在最前面」，
但 `:100` 的实现是 `OCR_DIRS = ("ocr_layout", "ocr_merged", "ocr_fix", "ocr")` ——
**注释与实现自相矛盾**，`ocr_layout` 才是第一顺位。

叠加 `:129-130`：`stage_layout` 的源取自 `ocr_dir()`，目标又写回 `ocr_layout/` →
**读自己上一次的输出**（自反馈），会永久压住更新的 `ocr_merged`。

真实风险链（三本都踩得上）：
```
layout(基于旧 ocr_fix) → apply_decisions 写入 ocr_merged → 再跑 md
  → ocr_dir 仍选中「旧的」ocr_layout → 裁决成果全部丢失，且无任何提示
```
这是 `REVIEW.md` 里记录的那个坑（当年是"忽略 ocr_merged"）的**变种**。

**P0-1 的分级判据（一刀切，不需词表、不需 jieba）**：

> **自动改写只允许"整词级替换"；凡是"单字替换 + 排除表"的一律降级为 audit 候选。**

- **A 级（保留自动，47 处）**：RULES 全 7 条 + CTX 里 6 条整词级（人门、推祟、陶治、异已、人口处、辨证论）

理由：整词级的错写法**本身不是中文词**（自已、人门、推祟），不存在"两种写法都成立"；
单字级的「人」几乎能与任意动词组合，排除表注定漏项——上面 3 处错改就是三处漏项的直接证明。

> ⚠️ 接口兼容：`fix.apply()` 保持返回**三元组**，候选塞进 `detail[i]["action"]`
> （`"fix"`/`"candidate"`），避免打断 `make_md.py:30` 与现有测试。

**P1-3 apply_decisions 配置化**——现状三个硬伤，实测确认：
1. **不幂等**：对已应用的 `ocr_merged` 再跑一次 → "将应用 0 处" + 6 条"未定位（原文已变？）"的误导告警
2. **静默丢失**：硬编码 20 条裁决里 **#3、#18 因"多差异段"被跳过，从未生效**（`apply_decisions.py:66-69`）
3. **下标寻址**：`queue[idx-1]`（`:63`），队列顺序一变裁决整体错位

新 schema `out/decisions.json`：`key="page@y0"` 稳定主键、`verdict ∈ A|B|C|?`、
`replacement` 支持整行覆盖（解决多段差异）、`status` 回写实现幂等；
**CLI 默认改为 dry-run**（现在默认是原地覆写），备份改"一次运行一个时间戳目录"。

> 可完整溯源：`ocr_merged` 相对 `ocr_fix` 的 **33 处**改动 = **27 处 disagree-B + 6 处 decision-B + 0 其它**。
> 也就是说当前成书的质量依赖这两张"工作目录里的一次性裁决"，**目前无法复现**。

**P1-4 disagree 不进 `all`**（与审阅意见的建议相反），理由：
- 只有 `out/` 那本有 `ocr_alt`；另两本没有 → 要么静默跳过（骗人）要么 `sys.exit`（把可用流程变不可用）
- 它有 `--apply` 会改变 md 的输入源，塞进 `all` 会破坏"旧书逐字节一致"的回归承诺
- 需要 jieba，而 `NEED_PKGS` 不含 → 缺依赖时会让跑了 2.6 分钟 OCR 的全流程死在最后一步

改为独立子命令 + `all` 末尾提示。实测 `disagree --a ocr_fix --b ocr_alt` 输出
306 页 / 196 处（A=37、B=27、?=132），与仓库 `out/disagree.json` **完全一致**（确定性可复现）。

## 5. P2 —— 一个月内 / 以及明确"不做"的

### 5.1 不做：跨页合段改"缩进优先"（实测净劣化）

审阅意见认为「缩进优先，标点兜底」更好。实测**证伪**，两个原因：

**① 跨页时"新页首行缩进"不可靠可得。** `layout.py:1084-1087` 的 `left` 是**逐页独立的**
（每页按 x0 取 10% 分位），`ind = L["x0"] - left[pi]` 在跨页时等于**用两页各自的零点相减**。
实测 left 偏离全书中位数 > 0.6bw 的页：黑格尔 **231/305（75.7%）**、规训 133/377、僧官 83/329。
极端例：规训 p001 的 `assemble` left=5 而 `qa` left=965（同一页两套基准差 9.5 字宽）。

**② 翻转方向是错的。** 改后翻转：黑格尔 22 / 规训 32 / 僧官 53 处，且主流方向是
**"本该分段 → 被并成续段"**（黑格尔 13/20、规训 16/20）。决定性反例：

| 书 | 页 | 新页首行 | 后果 |
|---|---|---|---|
| 规训 | p199 | **第二章** | **章标题被并进上一段** |
| 规训 | p207 | **规范化裁决** | **节标题被并进上一段** |
| 规训 | p112 | `(Beccaria, 87)。` | 页末注文被并进正文 |
| 僧官 | p053 | `=:.=.` | OCR 噪声行被当成段首 |

产物实测：黑格尔段落 407→399、超长段（>800 字）143→**145**、最长段 2013→**2262** 字；规训段落 1167→1148。
**净劣化。**

**替代方案（推荐，风险 低）**：**默认关闭「缩进优先」，只收集"标点与缩进互相矛盾"的候选清单**
（`report.json` 新增 `cross_suspect`，带 `ind`、`left_prev/left_cur`、`trusted` 标记），
默认行为 `newp = prev_ends` 与现状**完全等价 → book.md 逐字节不变**。
候选条数正好等于翻转数：22 / 32 / 53，与 `qa.txt` 的 17/37/47 是**不同口径**（qa 用的是众数 left + 物理首末行 +
含目录页），不能逐条对账，只能做方向性参考。

### 5.2 P2-1：bench.py + 机器可读回归（**最高优先级**，4~6 人时）

仓库零 fixture，样本必须自造并提交：**10 页 `ocr_layout` JSON × 2 本 ≈ 110 KB**
（规训 54,472 B + 僧官 55,174 B；单页中位数 5,461 B）。页面 PNG 每页 145 KB，**不入库**。

bench 只跑 `md/qa/epub` 三段（纯标准库零依赖），实测 10 页 **85 ms**、真书 360~1091 ms。
输出 JSON 含：`stages`(md/qa/notes/epub) + `params`（阈值快照）+ `book_md/page_map` 双哈希 + `golden_deltas`。
它是 §5.3 的替代品，也是防止 HANDOFF 数字再次漂移的唯一手段。

### 5.3 不做：阈值外部化为配置文件

审阅意见建议做，**明确建议不做**：
- 高风险阈值旁边都写着**实测依据**（`layout.py:442` 的 0.09 ←「正文首行最低 9.98%」、`:391` 的 ≥6 行、
  `:894` 的 0.72、`:799` 的 0.80）。挪进 YAML 后**证据与代码分离**，下次改的人看不到为什么是这个数。
- 项目硬约束是**零第三方依赖**（除 OCR 相关），加 YAML 要么破坏约束，要么用 JSON 失去可读性。
- 会让"换一本书静默出错"**更严重**：配置写错/缺键/忘改都无 diff 可见——而静默出错正是本项目的头号风险。

**替代方案（1.5 人时）**：阈值收成模块级常量（保留旁边的实测注释）+ bench 输出 `params` 快照 +
给 `head_band`/`page_offset` 加间隙自检告警。

### 5.4 P2-2：logging（收敛为 12 处，3~4 人时）

全项目 75 处 `print(`：**只改 12 处**（`layout.py:1301` 库内越界、`repair.py:92` 明细、
`bookflow.py:116` 警告、`epub3.py:335/342/347/352/359` 五个校验失败、`make_md.py` 未命中明细 3 行）。
其余约 50 处（`bookflow.py:57` 的 `"$ cmd"` 回显、run_ocr/run_layout 进度）**保持 print**——
那是可复制的命令回显与 CLI 体验，塞进 logging 反而变差。新增 `log.py`（纯标准库），日志走 stderr、进度留 stdout。

### 5.5 P2-3：脚注弹窗率提升（审阅意见的"最大收益项"，但两条主推方案被证伪）

审阅意见建议「对上标小字单独识别」+「脚注区局部放大重识别」。**实测两条都不成立**：

| 原方案 | 实测结果 | 判定 |
|---|---|---|
| a) 按字高 < 正文 60% 挑上标 | 僧官 9,544 行里 h<0.6·bh 仅 20 行、**含圈号 0 行**；规训 10,183 行里 24 行全在 footnote 区、**含圈号 0 行**；`return_word_box=True` 时星号**不出现在任何 word box** | ❌ 上标根本没被检出，不是阈值问题 |
| b) 脚注区 2×/3× 放大重识别 | 规训全部 83 个注页重跑（109.4 s）：带星号行 **18 → 4**，仅 2 页变好；且僧官 `pages/` 已 prune、仓库无源 PDF | ❌ 无效且不可执行 |

**改推两个替代方案**：

| 方案 | 做法 | 改动 | 工作量 | 预期收益 |
|---|---|---|---|---|
| **a′ 无注号单注页结构化锚定** | 僧官 110 个"零圈号"注页里 **82 页只有 1 条注** → 该注直接锚到本页正文，无需注号 | +40 行 | 3~4 人时 | 僧官 36.4% → **54.5%** |
| **c2 星号注缩进切块改进** | PP-DocLayoutV3 不给"每条注一框"（83 页 111 框 / 168 行），改为先合并再校验块数/句末 | +35 行 | 4~5 人时 | 规训 78.9% → **95~100%** |

合计 **+102 条弹窗**，两书弹窗率 43.8% → **62.4%**。比原方案收益低，但**能做出来**。
