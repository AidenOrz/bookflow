# MEMORY — 事实速查、约定、踩过的坑

## 环境事实（开发机）

下面这些是**开发验证时的实际环境**，不是硬性要求。项目代码本身不依赖任何绝对路径。

| 项 | 值 |
|---|---|
| Python | 3.13 |
| 依赖 | rapidocr 3.10 + onnxruntime-directml + Pillow + numpy + jieba + rapid_layout |
| PATH 上的 python | 开发机上 PATH 的 python 是 anaconda，**没有** rapidocr，别用它跑本项目 |
| GPU | RTX 3060 Laptop 6GB，ONNX 只有 `DmlExecutionProvider`（无 CUDA toolkit） |
| poppler | `pdftoppm` 必须在 PATH 上（render 阶段调用） |
| EPUB 构建 | 本项目自带 `epub3.py`（纯标准库），无外部依赖 |
| pandoc | 开发机上为 3.8；仅用于对比实验，流水线不依赖它 |
| java | 开发机没有 java，因此跑不了 epubcheck（用 `check_epub.py` 替代） |
| 样式表 | `assets/style.css`，`make_epub.py --css` 可换 |
| 版面模型 | `rapid_layout` 的 `pp_doc_layoutv3.onnx`，随 rapidocr 一并安装 |

## 约定

- 临时文件一律 `.tmp-` 前缀，任务结束后清干净。
- 产物写盘要**原子**（先 `.tmp` 再 `os.replace`），别留半成品。
- JSON 读写统一走 `jsonio.read/write`，避免 Windows 上句柄不释放。
- 新增阈值前先想：这个数是不是只对某本书成立？

## 踩过的坑（每条都真实发生并已修）

### 1. 页眉带阈值写死 10.5% → 吃掉正文首行
《黑格尔辩证法讲演录》书眉实测只到 **7.76%** 页高，而 5 页的正文首行落在
9.98%~10.48%，被当成书眉整行删掉（共 145 字），成书里上下文硬接成
「…机械因果律来进行推理时间差"，都是利用…」。
**修法**：`head_band()` 从学到的书眉位置反推阈值，上限压到 9%。

### 2. 标题折行只往前消费 → 残片漏进正文
「第五讲 / 黑格尔辩证法的逻辑学、认识论、本体 / 论的统一」三行标题，
命中中间行，第三行「论的统一」作为孤立段落进了成书。
**修法**：前后都扫，判据 = 是标题子串 + 字号 > 1.12 字宽。

### 3. 残片判据放宽到「子串」→ 误吞正文
正文末尾单独成行的「的。」被当成标题残片删掉（单字 + 是标题子串）。
**修法**：至少 2 个字，且字号必须明显大于正文。

### 4. 两个正则互逆 → 报了 2 处「修正」但净改动为 0
`己经→已经` 与 `自已经→自己经` 同时存在于 RULES，顺序是短→长，
导致「他自己经常」被改两次改回原样，report.json 却记 2 处修正。
**修法**：删掉全局的 `己经`，改成带 `(?<![自知己])` 后顾的上下文规则；统计改成**净改动**。

### 5. `fix.py` 全局替换误伤正确原文
「辨证论治」→「辩证论治」、「射人先射马」→「射入先射马」、「中国人口处于」→「中国入口处于」。
**修法**：全部改成带否定前瞻的上下文规则，并写了 29 条正负例测试。

### 6. 空输入静默成功，写出 0 字节成书、退出码 0
`make_md.py --src <不存在>` 打印「页数 0 条目 0」就结束。
**修法**：`layout.build()` 对空页列表 `raise SystemExit`；各阶段校验上游产物。

### 7. 目录条目 `page=None` 时 `%d` 崩溃，留下半成品
`make_md.py` 打印时崩在中间，此时 book.md/qa.txt 已落盘、report.json 缺失。
**修法**：`%d` → `%s` 并支持 None；三个产物原子写。

### 8. `ocr_dir()` 只比文件个数 → 忽略 ocr_merged / 直接 FileNotFoundError
work 目录里明明有 `ocr_merged`（含 64 处词表回填 + 6 处裁决），
md 阶段却读了 `ocr_fix`，README 的成果复现不出来。
**修法**：按 `ocr_layout > ocr_merged > ocr_fix > ocr` 优先级探测，并加 `--ocr-src` 显式指定。

### 9. `--force` 只对 render 生效 → 换模型重跑 OCR 静默什么都不做
`python bookflow.py ocr --model medium --force` 打印「待处理 0」、退出码 0。
**修法**：`--force` 透传到 `run_ocr.py`，删除已存在的页级 JSON 后重跑。

### 10. 源 PDF 末尾 19 页完全重复 → 成书成段重复
《中国僧官制度史》p332~p350 的 PNG 逐像素相同（扫描拼接时的重复）。
**修法**：`dedupe_pages()` 按清洗前文本判重，连续 ≥3 次才保留第一页。

### 11. 整页只剩水印的空白页 → 水印漏进正文
p054 是空白页，只有底部一行水印。旧的页眉带规则受 `len(p["lines"]) > 3` 保护，
单行页永远删不掉那行水印。
**修法**：跨页重复文本（`heads`）的判断提到位置带判断**之前**且不受行数保护；
同时把 `learn_running_heads` 的长度上限从 30 放宽到 60（整行水印约 40 字）。

### 12. `qa.py` 的 DUP_PARA 永不触发
book.md 是「一段一行 + 空行分隔」，空行把 `prev` 清掉了，相邻非空行永远不会相等。
**修法**：维护全书段落计数 + 相邻比较两套判据。

### 13. qa 的"跨页断句"是 87.8% 的哨兵值，没有区分度
中文书段落跨页本来就"不收句"，而真正丢的 5 行全淹没在这 267 条里。
**修法**：改成「上页未收句 + 新页首行缩进」/「上页已收句 + 新页顶格」两种矛盾组合，
实测从 267 条降到 17 条，并输出明细。

### 14. `cmp_ocr.py` 的置信度分母用错
medium 的总得分除以了 **small 的行数**（11249 vs 11095），算出 0.9812，真均值是 0.9948。
README 里的"medium 置信度更低"结论因此失真。
**修法**：两个版本各自计数。

### 15. 版面分析会误删吗？——不会，但要区分「脚注」与「版权页」
接入 PP-DocLayoutV3 后成书汉字从 162,733 降到 151,836（-10,897）。
逐块核对发现：99% 是**版权页**（CIP 数据在旧版里被重复输出 5 次）和**脚注**，正文没有丢。
判断方法：把前后两版按 100 字不重叠切块，逐块查是否在对方里。

### 16. 封面裁切：亮区判据对深色封面失效
油画类封面整页偏暗，`_longest_run(mean > 200)` 只裁出 74px 宽的一条，生成一张几乎全白的封面。
**修法**：改用**墨迹外接矩形**（低于纸色 90 分位的像素），再按「密度 < 35%」裁掉底部水印带。

### 17. 脚注被当正文剔除 → 学术书丢了半本书
PP-DocLayoutV3 标出 `footnote` 区后，旧代码直接 `DROP_REGIONS` 丢掉，注释全没了。
**修法**：`extract_notes()` 抽出成条目，`plan_notes()` 决定能否内联，其余降级成页尾注。
一条都不能丢——学术书的注就是正文的一部分。

### 18. 按顺序盲配注号 → 把并列项错接成脚注
正文里的 ①②③ 既可能是注号，也可能是并列项编号（本书大量如此）。
一度想用「注号数 == 注条数 → 按顺序配对」提高锚定率，实测新增的 26 对里
**书名重合率 0/26**，几乎全是错配。
**修法**：只在「本页正文恰好一个该号 + 注区恰好一条同号」时才内联，对不上就降级。
宁可 36% 的锚定率，也不能让读者点开看到不相干的引文。

### 19. 目录层级：`第X章` 与 `第X节` 命中同一个前缀模式
`L1_PAT` 同时匹配章和节，直接按它判级会把 36 个节也标成一级，整本书拍平成一个列表。
**修法**：`assign_levels()` 先给前缀排名次（章 10 / 节 20 / 一、 30 / 1. 40），
再映射成本书实际出现的几档。无编号条目（`（附说）…`）按**前一条的级别**定，
不能用缩进——居中排版的标题 x0 会和缩进的节标题重合（实测都落在 400 附近）。

### 20. 目录页的「目 录」两个大字被当成条目前缀
OCR 把「目」「录」拆成两块，且字号大到单独聚成一行，于是下一条真条目被粘成
「目序…牟钟鉴」。
**修法**：`parse_toc` 里跳过标题为「目」「录」「目次」「目录」的行。
注意别把引导点也一起剥掉：`序…牟钟鉴` 里的单个 `…` 是标题自带的分隔，
只有连续 2 个以上才是版面装饰。

### 21. pandoc 会把页尾注（`> ① …`）误判成有序列表
`> 1. xxx` 这种页尾注经 pandoc 转 EPUB 后变成 `<ol type="1">`，实测新书 41 处。
另外 pandoc 的脚注默认排在**文件末尾**（`footnotes-end-of-document`），长章要翻很远。
**结论**：脚注语义必须自己拼 XML，详见 `docs/architecture.md` 第 6 节。

### 22. 目录页只有一页时，旧规则永远判不出来
`detect_toc_pages` 原来要求「相邻页也是目录」，否则只看「行尾数字 ≥6」。
《规训与惩罚》整本只有一页「目 录」，于是候选页只有它自己，
prev_ok / next_ok 都不成立 → 返回空集 → `parse_toc` 里 `W` 没被赋值 →
`UnboundLocalError` 直接崩（这是本书最早的报错）。
**修法**：加一条单页即可成立的证据——**行尾页码严格递增**。目录的页码是章节
起始页，必然升序；版权页也有 7 个行尾数字（年份/开本/版次），但顺序乱，
这条恰好把两者分开。实测版权页升序对 3/6，目录页 11/11。

### 23. `第X部分` 与 `第X章` 共用层级名次 → 整本目录拍平
`RANKS` 里 `第X[讲章篇卷部编]` 是一条正则，于是「第一部分」和「第一章」同名次 10，
`assign_levels` 把它们映射成同一级，16 条目录全变一级、章全挂在 part 下看不出层次。
**修法**：`第X[部编卷篇]` 单独一档（名次 5），`第X[讲章]` 保持 10。
不分部的书（僧官制度史）不出现这一档，映射自然回退，两本书共用一套规则。

### 24. 目录页上 1 位页码被「边栏单字」规则删掉
`clean_page` 的边栏单字规则（`elen <= 2` 且贴版心外）本意是删书脊竖排残字，
但目录页的页码「3」x0=1827 越过了 `br - 0.5bw = 1802`，长得完全一样。
删掉后该条目拿不到页码，正文匹配只能靠猜。
**修法**：整条规则加 `not keep_nums` 前置条件。目录页保留页码，正文页照删。

### 25. 章节撞到「分部扉页」→ 正文整段被吞（最隐蔽的一个）
本书第 7/85/157/263 页是部分扉页，每个扉页把该部分的章名**重列一遍**
（「第二部分 / 惩罚 / 第一章 普遍的惩罚 / 第二章 惩罚的温和方式」）。
常规的「顺序单调 + 相似度」匹配在第 157 页一次撞上三章的标题，三章的起始页
全被算成同一页，中间的正文全被当成标题之前的垃圾吞掉。
症状是「命中 11/16」且章节结构里同一页出现三次。

**修法**：新增 `page_offset()` 学「PDF 页序 = 印刷页码 + 偏移」（本书偏移 6，
295/297 页吻合），匹配时先按页码落到目标页找标题，命中即采信（不做全局搜索）。
命中 11/16 → 16/16，层级 2/9 → 4/12。

**注意**：`number` 区域是这条的前提。版面分析漏标页码，就退化成纯文本匹配。

### 26. 「参考书目」被版面模型标成 `header` → 整章凭空消失
p361 的「参考书目」在 y=20.4% 页高处（左右居中），而真正的书眉都在 10~13%，
版面模型仍把它标成 `header`，`DROP_REGIONS` 一丢，这一章就没了。
**修法**：`header` 区域但 `y0 > max(band_top, 0.14)` 页高时保留——位置证据优先
于区域标签。真正的书眉落在带内，照旧删。

### 27. 星号注不能靠「注文里数星号」配对
本书脚注用 `*` / `**` / `***` 而不是圈号，且注区的星号在 OCR 后**大量丢失**
（168 行注文只剩 6 行带星号）。按注文数星号完全配不上。

**修法**：从**正文侧**数星号（跳过行首的列表符号），注区按左缩进切块，再用两条
互不依赖的证据校验：① 块数 == 正文星号数；② 非末块以句末标点收尾（切错边界
几乎必然切在句中）。都过才配对，否则整页降级为页尾注。
实测 83 页中 63 页配对成功（75 条弹窗），20 页降级。

**坑**：星号通道接管的页必须从圈号通道里剔除，否则同一条注会落盘两遍
（实测 158 条 = 83 + 75）。

### 28. 校对清单只有字符位置 → 人无法翻到原书
`audit.py` 原本只给 book.md 的字符上下文。成书近两千个段落，人工核对等于重读一遍。

**修法**：`assemble()` 给每段带行级 `[(段内偏移, 页idx)]`，`to_markdown_with_pages()`
转成 `[(md偏移, PDF页)]` 写进 `report.json`，`audit.py` 用二分查找换算成页码并按页排序。

**修的过程中踩了四个坑**，每个都会让页码系统性偏移：

1. `blocks.append(("p", text, buf_page))` 传的是**同一个 list 对象**，下一次 `buf_page.clear()`
   会把已落盘的块改空 → page_map 只剩标题的十几条。必须 `list(buf_page)` 拷副本。
2. `emit()` 累加 `pos` 时没算 `"\n".join()` 插入的分隔符。1100 个块 ≈ 2200 个分隔符，
   偏移单调偏小，页码整体偏 3 页（「土气」记成 p360、实为 p357）。
3. 渲染时 `txt = raw.strip()` 吃掉了前缀空白，而段内偏移按未 strip 的串记。
   要减去 `len(raw) - len(raw.lstrip())`。
4. `pn`（页尾注）块最初没带页码，继承了前一个块的位置；且一个 pn 块里可能混着多页的注，
   必须逐条给页码（`[note_page[it["id"]] for it in rest]`），只给首条仍会偏。

验证方法：拿记录页码回原始 OCR 页做子串匹配，要求 20/20 命中。实测 19/20
（剩下一处是注块跨页聚合，属设计使然）。

## 容易误判的地方

- **「成书汉字变少」不等于丢了内容**：段落边界变化、版权页去重都会减少字数。
  核对方法是用不重叠的固定长度块做包含检查，别用相邻行 diff。
- **脚注锚定率低 ≠ 算法差**：新书 110/243 个有脚注的页面，正文里一个圈号都没被
  识别出来。这是 OCR 漏识别上标小字，改匹配规则无效。
- **`epub3.py` 的 id 必须文件内唯一**：`fn-<id>` 与 `fnref-<id>` 都在同一个 XHTML 里，
  同一注被引用两次会产生重复 id（部分阅读器会拒绝打开）。`render_chapter` 用
  `seen` 集合去重，改动时要保住。
- **`epub3.validate` 会检查跨引用**：`href="#fn-x"` 必须有 `id="fn-x"` 对应，
  这是防「点开空白弹窗」的硬闸门。
- **`learn_running_heads` 的判据是"跨页 ≥5 次重复"**：测试里如果每页正文内容相同，
  会被误学成书眉。写测试数据时每页正文必须不同。
- **位置证据要压过区域标签**：版面模型把居中大字的章标题标成 `header` 是常事
  （规训与惩罚的「参考书目」y=20.4%）。凡是用 `region` 做删除判据的地方，
  都要有一条「位置明显不符就保留」的例外。
- **目录解析失败 ≠ 目录页不存在**：`parse_toc` 返回空列表时先看 `detect_toc_pages`
  返回什么。只有一页目录的书，旧规则需要「相邻页」证据，天然判不出来。
- **分部扉页是章节匹配的陷阱**：扉页会重列该部分的章名，纯文本相似度匹配必然
  撞车。条目带印刷页码时优先用页码锚定，别信相似度。
- **星号注和圈号注是两套完全不同的匹配逻辑**：前者的编号是星号个数，后者是圈号
  数值；并且星号在注区极易丢失。不要试图用一套代码处理两者。
- **改 `layout.py` 后必须跑旧书回归**：僧官制度史的正确输出是
  `103/103 命中 / 层级 {1:12, 2:40, 3:51} / 脚注 453(165+288) / 163,090 汉字`，
  这几个数字只要有一个变了，就是引入了回归。
- **`char_width()` 依赖 `L["w"]` 字段**，它由 `clean_page` 计算，原始 JSON 里没有。
  在 `clean_page` 之外调用要先补上这个字段。

## 2026-11-13 新增踩坑（P0/P1 这一轮）

### 8. `fix.py` 的排除表在成书里改坏了 3 处正确原文
「引人人胜」被 `引人→引入` 改成「引入人胜」、「税收人说」被 `收人→收入` 改成「税收入说」、
「不引人怀疑」被改成「不引入怀疑」。三处都造出了中文里不存在的词，**已落盘在规训成书里**。
根因：`X + 人 + 动词` 是**开放集**，排除表只能枚举见过的搭配。
**修法**：承认排除表不可能穷尽——补掉已知三处漏洞（「引人人胜」进 AUTO 组、「引人」排除表加
「人/怀疑」、「收人」加「说」），并留 `--conservative-fix` 一键退回「单字级只出候选」。
**教训**：任何「有限白名单 + 开放语法」的规则，都要假设它会漏，并留降级开关。

### 9. `ocr_layout` 静默反压 `ocr_merged`
`OCR_DIRS` 把 `ocr_layout` 排第一（它确实多了 region 标签），但先跑 layout、再回填 `ocr_merged`
时，顺序不变、选中的还是旧的 `ocr_layout`，**裁决成果全部丢失且无任何提示**。
叠加 `stage_layout` 的源取自 `ocr_dir()` 又写回 `ocr_layout`，等于读自己上一次的输出，
让 `ocr_layout` 的 mtime 永远最新、永久压住更新的 `ocr_merged`。
**修法**：`ocr_dir()` 加 mtime 新鲜度比较并告警；`stage_layout` 源排除 `ocr_layout` 自身。
**注意**：不要改 `OCR_DIRS` 的顺序——会改变两本验证书的选源，属行为变更。

### 10. 「跨页缩进优先」实测是净劣化，不要做
外部审阅建议跨页合段改成「缩进优先、标点兜底」。实测三本书翻转 22/32/53 处，
且主流方向是**把该分段的并成续段**：规训 p199 的章标题「第二章」、p207 的节标题
「规范化裁决」、p112/121/295 的页末注文都会被并进上一段；僧官 p053 的 OCR 噪声行
`=:.=.` 反被当成段首。
根因：`left` 是**逐页独立**算的（`layout.py:1084-1087` 取每页 x0 的 10% 分位，
`qa.py` 又用众数），跨页时等于拿两页各自的零点相减。黑格尔 **231/305 页（75.7%）**
的 left 偏离全书基准 >0.6 字宽，判据根本不可靠。
**结论**：保留标点判据；若要改进只能「标点与缩进矛盾时输出候选清单」，不能硬判。

### 11. `check_env` 用一个大元组检查依赖 → 两个方向都错
旧版 `NEED_PKGS = (rapidocr, PIL, numpy)` 对所有阶段生效：
md 阶段被 `rapidocr` **误拦**（`make_md.py` 根本不 import 它），而 layout 真正缺的
`rapid_layout` 又没检查 → 用户看到的是一段 `run_layout.py` 内部的 ModuleNotFoundError。
**修法**：`BASE_PKGS` + `STAGE_PKGS` 按阶段查；`audit`/`disagree` 单独 `check_dict()`（jieba）。

### 12. 无目录页时静默成功，产出无章节结构的书
`entries == []` 时全书拍成一个平面段落流，EPUB 只有一章、无导航，但 **rc=0、无告警**。
用户拿到成书只会以为「这书本来就这样」。
**修法**：`layout.build()` 打醒目告警并写 `report.json` 的 `toc_warning`。

### 13. `apply_decisions` 不幂等，且多差异段裁决被静默丢弃
对已应用过的目录再跑一次会打印「将应用 0 处」+ 6 条「未定位到（原文已变？）」的假告警；
更严重的是硬编码 20 条裁决里 #3、#18 因「多差异段」被跳过，**从未生效且无提示**。
**修法**：`key=page@y0` 稳定主键取代列表下标；`verdict=C` 支持整行覆盖；三态判定
（当前行==A → apply；==目标 → already；其它 → missing）实现幂等；默认 dry-run。
