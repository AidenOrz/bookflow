# MEMORY — 事实速查、约定、踩过的坑

## 环境事实（开发机）

下面这些是**开发验证时的实际环境**，不是硬性要求。项目代码本身不依赖任何绝对路径。

| 项 | 值 |
|---|---|
| Python | 3.13 |
| 依赖 | rapidocr 3.10 + onnxruntime-directml + Pillow + numpy + jieba + rapid_layout |
| PATH 上的 python | 开发机上 PATH 的 python 是 anaconda，**没有** rapidocr，别用它跑本项目 |
| GPU | RTX 3060 Laptop 6GB，ONNX 只有 `DmlExecutionProvider`（无 CUDA toolkit） |
| poppler | `pdftoppm` 必须在 PATH 上（render 阶段调用） |
| EPUB 构建 | 本项目自带 `epub3.py`（纯标准库），无外部依赖 |
| pandoc | 开发机上为 3.8；仅用于对比实验，流水线不依赖它 |
| java | 开发机没有 java，因此跑不了 epubcheck（用 `check_epub.py` 替代） |
| 样式表 | `assets/style.css`，`make_epub.py --css` 可换 |
| 版面模型 | `rapid_layout` 的 `pp_doc_layoutv3.onnx`，随 rapidocr 一并安装 |

## 约定

- 临时文件一律 `.tmp-` 前缀，任务结束后清干净。
- 产物写盘要**原子**（先 `.tmp` 再 `os.replace`），别留半成品。
- JSON 读写统一走 `jsonio.read/write`，避免 Windows 上句柄不释放。
- 新增阈值前先想：这个数是不是只对某本书成立？

## 踩过的坑（每条都真实发生并已修）

### 1. 页眉带阈值写死 10.5% → 吃掉正文首行
《黑格尔辩证法讲演录》书眉实测只到 **7.76%** 页高，而 5 页的正文首行落在
9.98%~10.48%，被当成书眉整行删掉（共 145 字），成书里上下文硬接成
「…机械因果律来进行推理时间差"，都是利用…」。
**修法**：`head_band()` 从学到的书眉位置反推阈值，上限压到 9%。

### 2. 标题折行只往前消费 → 残片漏进正文
「第五讲 / 黑格尔辩证法的逻辑学、认识论、本体 / 论的统一」三行标题，
命中中间行，第三行「论的统一」作为孤立段落进了成书。
**修法**：前后都扫，判据 = 是标题子串 + 字号 > 1.12 字宽。

### 3. 残片判据放宽到「子串」→ 误吞正文
正文末尾单独成行的「的。」被当成标题残片删掉（单字 + 是标题子串）。
**修法**：至少 2 个字，且字号必须明显大于正文。

### 4. 两个正则互逆 → 报了 2 处「修正」但净改动为 0
`己经→已经` 与 `自已经→自己经` 同时存在于 RULES，顺序是短→长，
导致「他自己经常」被改两次改回原样，report.json 却记 2 处修正。
**修法**：删掉全局的 `己经`，改成带 `(?<![自知己])` 后顾的上下文规则；统计改成**净改动**。

### 5. `fix.py` 全局替换误伤正确原文
「辨证论治」→「辩证论治」、「射人先射马」→「射入先射马」、「中国人口处于」→「中国入口处于」。
**修法**：全部改成带否定前瞻的上下文规则，并写了 29 条正负例测试。

### 6. 空输入静默成功，写出 0 字节成书、退出码 0
`make_md.py --src <不存在>` 打印「页数 0 条目 0」就结束。
**修法**：`layout.build()` 对空页列表 `raise SystemExit`；各阶段校验上游产物。

### 7. 目录条目 `page=None` 时 `%d` 崩溃，留下半成品
`make_md.py` 打印时崩在中间，此时 book.md/qa.txt 已落盘、report.json 缺失。
**修法**：`%d` → `%s` 并支持 None；三个产物原子写。

### 8. `ocr_dir()` 只比文件个数 → 忽略 ocr_merged / 直接 FileNotFoundError
work 目录里明明有 `ocr_merged`（含 64 处词表回填 + 6 处裁决），
md 阶段却读了 `ocr_fix`，README 的成果复现不出来。
**修法**：按 `ocr_layout > ocr_merged > ocr_fix > ocr` 优先级探测，并加 `--ocr-src` 显式指定。

### 9. `--force` 只对 render 生效 → 换模型重跑 OCR 静默什么都不做
`python bookflow.py ocr --model medium --force` 打印「待处理 0」、退出码 0。
**修法**：`--force` 透传到 `run_ocr.py`，删除已存在的页级 JSON 后重跑。

### 10. 源 PDF 末尾 19 页完全重复 → 成书成段重复
《中国僧官制度史》p332~p350 的 PNG 逐像素相同（扫描拼接时的重复）。
**修法**：`dedupe_pages()` 按清洗前文本判重，连续 ≥3 次才保留第一页。

### 11. 整页只剩水印的空白页 → 水印漏进正文
p054 是空白页，只有底部一行水印。旧的页眉带规则受 `len(p["lines"]) > 3` 保护，
单行页永远删不掉那行水印。
**修法**：跨页重复文本（`heads`）的判断提到位置带判断**之前**且不受行数保护；
同时把 `learn_running_heads` 的长度上限从 30 放宽到 60（整行水印约 40 字）。

### 12. `qa.py` 的 DUP_PARA 永不触发
book.md 是「一段一行 + 空行分隔」，空行把 `prev` 清掉了，相邻非空行永远不会相等。
**修法**：维护全书段落计数 + 相邻比较两套判据。

### 13. qa 的"跨页断句"是 87.8% 的哨兵值，没有区分度
中文书段落跨页本来就"不收句"，而真正丢的 5 行全淹没在这 267 条里。
**修法**：改成「上页未收句 + 新页首行缩进」/「上页已收句 + 新页顶格」两种矛盾组合，
实测从 267 条降到 17 条，并输出明细。

### 14. `cmp_ocr.py` 的置信度分母用错
medium 的总得分除以了 **small 的行数**（11249 vs 11095），算出 0.9812，真均值是 0.9948。
README 里的"medium 置信度更低"结论因此失真。
**修法**：两个版本各自计数。

### 15. 版面分析会误删吗？——不会，但要区分「脚注」与「版权页」
接入 PP-DocLayoutV3 后成书汉字从 162,733 降到 151,836（-10,897）。
逐块核对发现：99% 是**版权页**（CIP 数据在旧版里被重复输出 5 次）和**脚注**，正文没有丢。
判断方法：把前后两版按 100 字不重叠切块，逐块查是否在对方里。

### 16. 封面裁切：亮区判据对深色封面失效
油画类封面整页偏暗，`_longest_run(mean > 200)` 只裁出 74px 宽的一条，生成一张几乎全白的封面。
**修法**：改用**墨迹外接矩形**（低于纸色 90 分位的像素），再按「密度 < 35%」裁掉底部水印带。

### 17. 脚注被当正文剔除 → 学术书丢了半本书
PP-DocLayoutV3 标出 `footnote` 区后，旧代码直接 `DROP_REGIONS` 丢掉，注释全没了。
**修法**：`extract_notes()` 抽出成条目，`plan_notes()` 决定能否内联，其余降级成页尾注。
一条都不能丢——学术书的注就是正文的一部分。

### 18. 按顺序盲配注号 → 把并列项错接成脚注
正文里的 ①②③ 既可能是注号，也可能是并列项编号（本书大量如此）。
一度想用「注号数 == 注条数 → 按顺序配对」提高锚定率，实测新增的 26 对里
**书名重合率 0/26**，几乎全是错配。
**修法**：只在「本页正文恰好一个该号 + 注区恰好一条同号」时才内联，对不上就降级。
宁可 36% 的锚定率，也不能让读者点开看到不相干的引文。

### 19. 目录层级：`第X章` 与 `第X节` 命中同一个前缀模式
`L1_PAT` 同时匹配章和节，直接按它判级会把 36 个节也标成一级，整本书拍平成一个列表。
**修法**：`assign_levels()` 先给前缀排名次（章 10 / 节 20 / 一、 30 / 1. 40），
再映射成本书实际出现的几档。无编号条目（`（附说）…`）按**前一条的级别**定，
不能用缩进——居中排版的标题 x0 会和缩进的节标题重合（实测都落在 400 附近）。

### 20. 目录页的「目 录」两个大字被当成条目前缀
OCR 把「目」「录」拆成两块，且字号大到单独聚成一行，于是下一条真条目被粘成
「目序…牟钟鉴」。
**修法**：`parse_toc` 里跳过标题为「目」「录」「目次」「目录」的行。
注意别把引导点也一起剥掉：`序…牟钟鉴` 里的单个 `…` 是标题自带的分隔，
只有连续 2 个以上才是版面装饰。

### 21. pandoc 会把页尾注（`> ① …`）误判成有序列表
`> 1. xxx` 这种页尾注经 pandoc 转 EPUB 后变成 `<ol type="1">`，实测新书 41 处。
另外 pandoc 的脚注默认排在**文件末尾**（`footnotes-end-of-document`），长章要翻很远。
**结论**：脚注语义必须自己拼 XML，详见 `docs/architecture.md` 第 6 节。

## 容易误判的地方

- **「成书汉字变少」不等于丢了内容**：段落边界变化、版权页去重都会减少字数。
  核对方法是用不重叠的固定长度块做包含检查，别用相邻行 diff。
- **脚注锚定率低 ≠ 算法差**：新书 110/243 个有脚注的页面，正文里一个圈号都没被
  识别出来。这是 OCR 漏识别上标小字，改匹配规则无效。
- **`epub3.py` 的 id 必须文件内唯一**：`fn-<id>` 与 `fnref-<id>` 都在同一个 XHTML 里，
  同一注被引用两次会产生重复 id（部分阅读器会拒绝打开）。`render_chapter` 用
  `seen` 集合去重，改动时要保住。
- **`epub3.validate` 会检查跨引用**：`href="#fn-x"` 必须有 `id="fn-x"` 对应，
  这是防「点开空白弹窗」的硬闸门。
- **`learn_running_heads` 的判据是"跨页 ≥5 次重复"**：测试里如果每页正文内容相同，
  会被误学成书眉。写测试数据时每页正文必须不同。
- **`char_width()` 依赖 `L["w"]` 字段**，它由 `clean_page` 计算，原始 JSON 里没有。
  在 `clean_page` 之外调用要先补上这个字段。
