# MEMORY — 事实速查、约定、踩过的坑

## 环境事实（开发机）

下面这些是**开发验证时的实际环境**，不是硬性要求。项目代码本身不依赖任何绝对路径。

| 项 | 值 |
|---|---|
| Python | 3.13 |
| 依赖 | rapidocr 3.10 + onnxruntime-directml + Pillow + numpy + jieba + rapid_layout |
| PATH 上的 python | 开发机上 PATH 的 python 是 anaconda，**没有** rapidocr，别用它跑本项目 |
| GPU | RTX 3060 Laptop 6GB，ONNX 只有 `DmlExecutionProvider`（无 CUDA toolkit） |
| poppler | `pdftoppm` 必须在 PATH 上（render 阶段调用） |
| EPUB 构建 | 本项目自带 `epub3.py`（纯标准库），无外部依赖 |
| pandoc | 开发机上为 3.8；仅用于对比实验，流水线不依赖它 |
| java | 开发机没有 java，因此跑不了 epubcheck（用 `check_epub.py` 替代） |
| 样式表 | `assets/style.css`，`make_epub.py --css` 可换 |
| 版面模型 | `rapid_layout` 的 `pp_doc_layoutv3.onnx`，随 rapidocr 一并安装 |

## 约定

- 临时文件一律 `.tmp-` 前缀，任务结束后清干净。
- 产物写盘要**原子**（先 `.tmp` 再 `os.replace`），别留半成品。
- JSON 读写统一走 `jsonio.read/write`，避免 Windows 上句柄不释放。
- **页级 JSON 与 report.json 必须盖 `pagedoc` 章**（`schema`/`schema_version`/`producer`），
  写入用 `pagedoc.stamp`，读取用 `pagedoc.read`（版本不认识会抛错）。
  新增一个写入方就必须在 `pagedoc.KNOWN_PRODUCERS` 里登记。
- 新增阈值前先想：这个数是不是只对某本书成立？

## 踩过的坑（每条都真实发生并已修）

### 1. 页眉带阈值写死 10.5% → 吃掉正文首行
《黑格尔辩证法讲演录》书眉实测只到 **7.76%** 页高，而 5 页的正文首行落在
9.98%~10.48%，被当成书眉整行删掉（共 145 字），成书里上下文硬接成
「…机械因果律来进行推理时间差"，都是利用…」。
**修法**：`head_band()` 从学到的书眉位置反推阈值，上限压到 9%。

### 2. 标题折行只往前消费 → 残片漏进正文
「第五讲 / 黑格尔辩证法的逻辑学、认识论、本体 / 论的统一」三行标题，
命中中间行，第三行「论的统一」作为孤立段落进了成书。
**修法**：前后都扫，判据 = 是标题子串 + 字号 > 1.12 字宽。

### 3. 残片判据放宽到「子串」→ 误吞正文
正文末尾单独成行的「的。」被当成标题残片删掉（单字 + 是标题子串）。
**修法**：至少 2 个字，且字号必须明显大于正文。

### 4. 两个正则互逆 → 报了 2 处「修正」但净改动为 0
`己经→已经` 与 `自已经→自己经` 同时存在于 RULES，顺序是短→长，
导致「他自己经常」被改两次改回原样，report.json 却记 2 处修正。
**修法**：删掉全局的 `己经`，改成带 `(?<![自知己])` 后顾的上下文规则；统计改成**净改动**。

### 5. `fix.py` 全局替换误伤正确原文
「辨证论治」→「辩证论治」、「射人先射马」→「射入先射马」、「中国人口处于」→「中国入口处于」。
**修法**：全部改成带否定前瞻的上下文规则，并写了 29 条正负例测试。

### 6. 空输入静默成功，写出 0 字节成书、退出码 0
`make_md.py --src <不存在>` 打印「页数 0 条目 0」就结束。
**修法**：`layout.build()` 对空页列表 `raise SystemExit`；各阶段校验上游产物。

### 7. 目录条目 `page=None` 时 `%d` 崩溃，留下半成品
`make_md.py` 打印时崩在中间，此时 book.md/qa.txt 已落盘、report.json 缺失。
**修法**：`%d` → `%s` 并支持 None；三个产物原子写。

### 8. `ocr_dir()` 只比文件个数 → 忽略 ocr_merged / 直接 FileNotFoundError
work 目录里明明有 `ocr_merged`（含 64 处词表回填 + 6 处裁决），
md 阶段却读了 `ocr_fix`，README 的成果复现不出来。
**修法**：按 `ocr_layout > ocr_merged > ocr_fix > ocr` 优先级探测，并加 `--ocr-src` 显式指定。

### 9. `--force` 只对 render 生效 → 换模型重跑 OCR 静默什么都不做
`python bookflow.py ocr --model medium --force` 打印「待处理 0」、退出码 0。
**修法**：`--force` 透传到 `run_ocr.py`，删除已存在的页级 JSON 后重跑。

### 10. 源 PDF 末尾 19 页完全重复 → 成书成段重复
《中国僧官制度史》p332~p350 的 PNG 逐像素相同（扫描拼接时的重复）。
**修法**：`dedupe_pages()` 按清洗前文本判重，连续 ≥3 次才保留第一页。

### 11. 整页只剩水印的空白页 → 水印漏进正文
p054 是空白页，只有底部一行水印。旧的页眉带规则受 `len(p["lines"]) > 3` 保护，
单行页永远删不掉那行水印。
**修法**：跨页重复文本（`heads`）的判断提到位置带判断**之前**且不受行数保护；
同时把 `learn_running_heads` 的长度上限从 30 放宽到 60（整行水印约 40 字）。

### 12. `qa.py` 的 DUP_PARA 永不触发
book.md 是「一段一行 + 空行分隔」，空行把 `prev` 清掉了，相邻非空行永远不会相等。
**修法**：维护全书段落计数 + 相邻比较两套判据。

### 13. qa 的"跨页断句"是 87.8% 的哨兵值，没有区分度
中文书段落跨页本来就"不收句"，而真正丢的 5 行全淹没在这 267 条里。
**修法**：改成「上页未收句 + 新页首行缩进」/「上页已收句 + 新页顶格」两种矛盾组合，
实测从 267 条降到 17 条，并输出明细。

### 14. `cmp_ocr.py` 的置信度分母用错
medium 的总得分除以了 **small 的行数**（11249 vs 11095），算出 0.9812，真均值是 0.9948。
README 里的"medium 置信度更低"结论因此失真。
**修法**：两个版本各自计数。

### 15. 版面分析会误删吗？——不会，但要区分「脚注」与「版权页」
接入 PP-DocLayoutV3 后成书汉字从 162,733 降到 151,836（-10,897）。
逐块核对发现：99% 是**版权页**（CIP 数据在旧版里被重复输出 5 次）和**脚注**，正文没有丢。
判断方法：把前后两版按 100 字不重叠切块，逐块查是否在对方里。

### 16. 封面裁切：亮区判据对深色封面失效
油画类封面整页偏暗，`_longest_run(mean > 200)` 只裁出 74px 宽的一条，生成一张几乎全白的封面。
**修法**：改用**墨迹外接矩形**（低于纸色 90 分位的像素），再按「密度 < 35%」裁掉底部水印带。

### 17. 脚注被当正文剔除 → 学术书丢了半本书
PP-DocLayoutV3 标出 `footnote` 区后，旧代码直接 `DROP_REGIONS` 丢掉，注释全没了。
**修法**：`extract_notes()` 抽出成条目，`plan_notes()` 决定能否内联，其余降级成页尾注。
一条都不能丢——学术书的注就是正文的一部分。

### 18. 按顺序盲配注号 → 把并列项错接成脚注
正文里的 ①②③ 既可能是注号，也可能是并列项编号（本书大量如此）。
一度想用「注号数 == 注条数 → 按顺序配对」提高锚定率，实测新增的 26 对里
**书名重合率 0/26**，几乎全是错配。
**修法**：只在「本页正文恰好一个该号 + 注区恰好一条同号」时才内联，对不上就降级。
宁可 36% 的锚定率，也不能让读者点开看到不相干的引文。

### 19. 目录层级：`第X章` 与 `第X节` 命中同一个前缀模式
`L1_PAT` 同时匹配章和节，直接按它判级会把 36 个节也标成一级，整本书拍平成一个列表。
**修法**：`assign_levels()` 先给前缀排名次（章 10 / 节 20 / 一、 30 / 1. 40），
再映射成本书实际出现的几档。无编号条目（`（附说）…`）按**前一条的级别**定，
不能用缩进——居中排版的标题 x0 会和缩进的节标题重合（实测都落在 400 附近）。

### 20. 目录页的「目 录」两个大字被当成条目前缀
OCR 把「目」「录」拆成两块，且字号大到单独聚成一行，于是下一条真条目被粘成
「目序…牟钟鉴」。
**修法**：`parse_toc` 里跳过标题为「目」「录」「目次」「目录」的行。
注意别把引导点也一起剥掉：`序…牟钟鉴` 里的单个 `…` 是标题自带的分隔，
只有连续 2 个以上才是版面装饰。

### 21. pandoc 会把页尾注（`> ① …`）误判成有序列表
`> 1. xxx` 这种页尾注经 pandoc 转 EPUB 后变成 `<ol type="1">`，实测新书 41 处。
另外 pandoc 的脚注默认排在**文件末尾**（`footnotes-end-of-document`），长章要翻很远。
**结论**：脚注语义必须自己拼 XML，详见 `docs/architecture.md` 第 6 节。

### 22. 目录页只有一页时，旧规则永远判不出来
`detect_toc_pages` 原来要求「相邻页也是目录」，否则只看「行尾数字 ≥6」。
《规训与惩罚》整本只有一页「目 录」，于是候选页只有它自己，
prev_ok / next_ok 都不成立 → 返回空集 → `parse_toc` 里 `W` 没被赋值 →
`UnboundLocalError` 直接崩（这是本书最早的报错）。
**修法**：加一条单页即可成立的证据——**行尾页码严格递增**。目录的页码是章节
起始页，必然升序；版权页也有 7 个行尾数字（年份/开本/版次），但顺序乱，
这条恰好把两者分开。实测版权页升序对 3/6，目录页 11/11。

### 23. `第X部分` 与 `第X章` 共用层级名次 → 整本目录拍平
`RANKS` 里 `第X[讲章篇卷部编]` 是一条正则，于是「第一部分」和「第一章」同名次 10，
`assign_levels` 把它们映射成同一级，16 条目录全变一级、章全挂在 part 下看不出层次。
**修法**：`第X[部编卷篇]` 单独一档（名次 5），`第X[讲章]` 保持 10。
不分部的书（僧官制度史）不出现这一档，映射自然回退，两本书共用一套规则。

### 24. 目录页上 1 位页码被「边栏单字」规则删掉
`clean_page` 的边栏单字规则（`elen <= 2` 且贴版心外）本意是删书脊竖排残字，
但目录页的页码「3」x0=1827 越过了 `br - 0.5bw = 1802`，长得完全一样。
删掉后该条目拿不到页码，正文匹配只能靠猜。
**修法**：整条规则加 `not keep_nums` 前置条件。目录页保留页码，正文页照删。

### 25. 章节撞到「分部扉页」→ 正文整段被吞（最隐蔽的一个）
本书第 7/85/157/263 页是部分扉页，每个扉页把该部分的章名**重列一遍**
（「第二部分 / 惩罚 / 第一章 普遍的惩罚 / 第二章 惩罚的温和方式」）。
常规的「顺序单调 + 相似度」匹配在第 157 页一次撞上三章的标题，三章的起始页
全被算成同一页，中间的正文全被当成标题之前的垃圾吞掉。
症状是「命中 11/16」且章节结构里同一页出现三次。

**修法**：新增 `page_offset()` 学「PDF 页序 = 印刷页码 + 偏移」（本书偏移 6，
295/297 页吻合），匹配时先按页码落到目标页找标题，命中即采信（不做全局搜索）。
命中 11/16 → 16/16，层级 2/9 → 4/12。

**注意**：`number` 区域是这条的前提。版面分析漏标页码，就退化成纯文本匹配。

### 26. 「参考书目」被版面模型标成 `header` → 整章凭空消失
p361 的「参考书目」在 y=20.4% 页高处（左右居中），而真正的书眉都在 10~13%，
版面模型仍把它标成 `header`，`DROP_REGIONS` 一丢，这一章就没了。
**修法**：`header` 区域但 `y0 > max(band_top, 0.14)` 页高时保留——位置证据优先
于区域标签。真正的书眉落在带内，照旧删。

### 27. 星号注不能靠「注文里数星号」配对
本书脚注用 `*` / `**` / `***` 而不是圈号，且注区的星号在 OCR 后**大量丢失**
（168 行注文只剩 6 行带星号）。按注文数星号完全配不上。

**修法**：从**正文侧**数星号（跳过行首的列表符号），注区按左缩进切块，再用两条
互不依赖的证据校验：① 块数 == 正文星号数；② 非末块以句末标点收尾（切错边界
几乎必然切在句中）。都过才配对，否则整页降级为页尾注。
实测 83 页中 63 页配对成功（75 条弹窗），20 页降级。

**坑**：星号通道接管的页必须从圈号通道里剔除，否则同一条注会落盘两遍
（实测 158 条 = 83 + 75）。

### 28. 校对清单只有字符位置 → 人无法翻到原书
`audit.py` 原本只给 book.md 的字符上下文。成书近两千个段落，人工核对等于重读一遍。

**修法**：`assemble()` 给每段带行级 `[(段内偏移, 页idx)]`，`to_markdown_with_pages()`
转成 `[(md偏移, PDF页)]` 写进 `report.json`，`audit.py` 用二分查找换算成页码并按页排序。

**修的过程中踩了四个坑**，每个都会让页码系统性偏移：

1. `blocks.append(("p", text, buf_page))` 传的是**同一个 list 对象**，下一次 `buf_page.clear()`
   会把已落盘的块改空 → page_map 只剩标题的十几条。必须 `list(buf_page)` 拷副本。
2. `emit()` 累加 `pos` 时没算 `"\n".join()` 插入的分隔符。1100 个块 ≈ 2200 个分隔符，
   偏移单调偏小，页码整体偏 3 页（「土气」记成 p360、实为 p357）。
3. 渲染时 `txt = raw.strip()` 吃掉了前缀空白，而段内偏移按未 strip 的串记。
   要减去 `len(raw) - len(raw.lstrip())`。
4. `pn`（页尾注）块最初没带页码，继承了前一个块的位置；且一个 pn 块里可能混着多页的注，
   必须逐条给页码（`[note_page[it["id"]] for it in rest]`），只给首条仍会偏。

验证方法：拿记录页码回原始 OCR 页做子串匹配，要求 20/20 命中。实测 19/20
（剩下一处是注块跨页聚合，属设计使然）。

## 容易误判的地方

- **「成书汉字变少」不等于丢了内容**：段落边界变化、版权页去重都会减少字数。
  核对方法是用不重叠的固定长度块做包含检查，别用相邻行 diff。
- **脚注锚定率低 ≠ 算法差**：新书 110/243 个有脚注的页面，正文里一个圈号都没被
  识别出来。这是 OCR 漏识别上标小字，改匹配规则无效。
- **`epub3.py` 的 id 必须文件内唯一**：`fn-<id>` 与 `fnref-<id>` 都在同一个 XHTML 里，
  同一注被引用两次会产生重复 id（部分阅读器会拒绝打开）。`render_chapter` 用
  `seen` 集合去重，改动时要保住。
- **`epub3.validate` 会检查跨引用**：`href="#fn-x"` 必须有 `id="fn-x"` 对应，
  这是防「点开空白弹窗」的硬闸门。
- **`learn_running_heads` 的判据是"跨页 ≥5 次重复"**：测试里如果每页正文内容相同，
  会被误学成书眉。写测试数据时每页正文必须不同。
- **位置证据要压过区域标签**：版面模型把居中大字的章标题标成 `header` 是常事
  （规训与惩罚的「参考书目」y=20.4%）。凡是用 `region` 做删除判据的地方，
  都要有一条「位置明显不符就保留」的例外。
- **目录解析失败 ≠ 目录页不存在**：`parse_toc` 返回空列表时先看 `detect_toc_pages`
  返回什么。只有一页目录的书，旧规则需要「相邻页」证据，天然判不出来。
- **分部扉页是章节匹配的陷阱**：扉页会重列该部分的章名，纯文本相似度匹配必然
  撞车。条目带印刷页码时优先用页码锚定，别信相似度。
- **星号注和圈号注是两套完全不同的匹配逻辑**：前者的编号是星号个数，后者是圈号
  数值；并且星号在注区极易丢失。不要试图用一套代码处理两者。
- **改 `layout.py` 后必须跑旧书回归**：僧官制度史的正确输出是
  `103/103 命中 / 层级 {1:12, 2:40, 3:51} / 脚注 453（165 弹窗 + 288 页尾注）/
  163,425 汉字 / 插图 4 / table 块 7`。这几个数字只要有一个变了，就是引入了回归。
  **要分「有没有 `pages/`」两种情况**（2026-11-16 修订）：
  | 场景 | `book.md` 文件 SHA256 前缀 | 字符 | 汉字 | 插图 | table 块 |
  |---|---|---|---|---|---|
  | 有 `pages/` | `0BA1E017…` | 200,820 | 163,425 | 4 | 7 |
  | 无 `pages/`（图降级） | `CA2B25F4…` | 204,882 | 163,576 | 0 | 11 |

  两档都是 2026-11-16 按新规则实测的。无 `pages/` 那档字符更多，因为 4 张图降级成
  table 块、把图区的 OCR 文字保留了下来（汉字多 151，正是图区里的字）。

  **哈希口径必须说清楚**：`book.md` 在 Windows 上以 `\r\n` 落盘，所以
  「文件字节 SHA256」（`Get-FileHash`）与「内存字符串 SHA256」**不是同一个值**。
  本文档记的一律是**文件字节**哈希，复算用 `Get-FileHash book.md -Algorithm SHA256`。
  三本书的文件字节哈希（2026-11-16 实测）：僧官 `0BA1E017…`、规训 `E5053BDD…`、
  黑格尔 `320A586E…`。**规训的哈希在本轮改动前后逐字节不变**，这是「没有副作用」的锚点。

### 8. `fix.py` 的排除表在成书里改坏了 3 处正确原文
「引人人胜」被 `引人→引入` 改成「引入人胜」、「税收人说」被 `收人→收入` 改成「税收入说」、

根因：`X + 人 + 动词` 是**开放集**，排除表只能枚举见过的搭配。
**修法**：承认排除表不可能穷尽——补掉已知三处漏洞（「引人人胜」进 AUTO 组、「引人」排除表加
「人/怀疑」、「收人」加「说」），并留 `--conservative-fix` 一键退回「单字级只出候选」。

### 9. `ocr_layout` 静默反压 `ocr_merged`
`OCR_DIRS` 把 `ocr_layout` 排第一（它确实多了 region 标签），但先跑 layout、再回填 `ocr_merged`
时，顺序不变、选中的还是旧的 `ocr_layout`，**裁决成果全部丢失且无任何提示**。
叠加 `stage_layout` 的源取自 `ocr_dir()` 又写回 `ocr_layout`，等于读自己上一次的输出，
让 `ocr_layout` 的 mtime 永远最新、永久压住更新的 `ocr_merged`。
**修法**：`ocr_dir()` 加 mtime 新鲜度比较并告警；`stage_layout` 源排除 `ocr_layout` 自身。
**注意**：不要改 `OCR_DIRS` 的顺序——会改变两本验证书的选源，属行为变更。

### 10. 「跨页缩进优先」实测是净劣化，不要做
外部审阅建议跨页合段改成「缩进优先、标点兜底」。实测三本书翻转 22/32/53 处，
且主流方向是**把该分段的并成续段**：规训 p199 的章标题「第二章」、p207 的节标题

`=:.=.` 反被当成段首。

`qa.py` 又用众数），跨页时等于拿两页各自的零点相减。黑格尔 **231/305 页（75.7%）**
的 left 偏离全书基准 >0.6 字宽，判据根本不可靠。
**结论**：保留标点判据；若要改进只能「标点与缩进矛盾时输出候选清单」，不能硬判。

### 11. `check_env` 用一个大元组检查依赖 → 两个方向都错

### 12. 无目录页时静默成功，产出无章节结构的书

### 13. `apply_decisions` 不幂等，且多差异段裁决被静默丢弃
对已应用过的目录再跑一次会打印「将应用 0 处」+ 6 条「未定位到（原文已变？）」的假告警；
更严重的是硬编码 20 条裁决里 #3、#18 因「多差异段」被跳过，**从未生效且无提示**。
**修法**：`key=page@y0` 稳定主键取代列表下标；`verdict=C` 支持整行覆盖；三态判定

### 14. 「字符类排除表」看着像笔误，实测比词组分支更安全（别看一眼就"修正"）
`fix.py` 的 `引人(?![注目入胜深思…])` 确实曾是笔误（本该写 `(?!(?:注目|入胜|…))`），
但真换成分支会**改坏书**：僧官成书里 OCR 把「引人注目」认成「引人注日」，分支表里没有
「注日」→ 默认模式把正确原文改成「引入注日」（实测换成分支后僧官成书变动 1 处，就是这处）。
字符类按**第二字**拦（「注」在集合里）就挡住了。代价是白名单外的搭配一并被放过
（引人思乡/引人往返/引人思考）= **漏改**方向，不会改坏正文；而过度匹配才会改坏书。
**教训**：`(?![单字])` 在 OCR 场景常常是**正确的粗略拦法**——它拦的是"后一个字长得像"，
而 OCR 错的偏偏是第二个字。改规则前先跑三本书回归，别只看语法「更规范」。

### 15. `apply_decisions` 与 `decisions` 的页名补零口径必须一致
`decisions.py` 生成裁决时有补零容错（`p-001.png.json` / `p-15.png.json` / `p-00015.png.json`），
`apply_decisions.plan()` 却直接拼 `page + ".json"` → 裁决里写 `p-1.png` 时回填全部 `missing`，
表现为「能生成裁决、就是回填不上」。**修法**：`_page_path` 提为公开 `page_path()` 两边共用。
**教训**：凡是"生成端有兼容逻辑、消费端自己拼路径"的地方，都是同一类 bug 的温床。

### 16. DocLayout-YOLO 不能替代 PP-DocLayoutV3（标签体系不兼容，不是精度问题）
`rapid_layout` 1.2.1 已内置 4 个 DocLayout-YOLO，不用装新依赖即可试。
**结论：不换。** 核心原因不是它不准，是它的「非正文」**只有一个类** `abandon`，
而 `layout.py` 要区分三类语义：脚注（抽注文→`noteref`）、书眉（丢）、页码（做锚定）。
docstructbench 的 `abandon` 实测构成 = 书眉 39.0% / 页码 38.4% / 脚注 19.2%，
拿到后无法分流。把结果原样喂给 `extract_notes`：脚注 11→0 条，正文膨胀 +3.0%。

| 模型 | 脚注 21 行真值 | 书眉 50 行 | 页码 49 行 |
|---|---|---|---|
| pp_doc_layoutv3 | 21/21 | 50/50 | 49/49 |
| docstructbench | 0（全 `abandon`） | 0 | 0 |
| docsynth | 0（81% 判成 `Text`） | 6% | 10% |
| d4la | 0（`Footer` 43%） | 4% | 86% |

二值化后（正文/非正文）一致率 99.49%（120 页 3115 行，分歧 16 行），但分歧两个方向
都有：净收益仅 5 行、全在封面页。**交叉验证的正当理由也不成立**——已知的「章标题被
标成 header」坑，拿 6 行去问它，5 行它判 `abandon`（同样认为该丢），投不出反对票。
**教训**：换模型前先问「它的标签能不能直接映射到我的决策分支」，不能映射的模型，
即使二值一致率 99% 也等于没用。详见 `docs/README.md`「DocLayout-YOLO 实测」。

### 17. 有文字层的书，我们原来在白跑 OCR（98.85% 的字已经在那里了）
实测一本有完好文字层的 PDF（927 页，《武汉地区文革纪实》），抽样 13 页逐字对比：

```
文字层 9,652 汉字  |  OCR 9,584 汉字  |  相同 9,541  |  整体相似度 98.85%
OCR 每页 17.6 s（13 页 229 s）  |  pdftotext 取同样页几乎瞬时
```
也就是说**我们花了 4 小时做的 98.85% 已经免费在那儿了**，只有 1.15% 是我们额外挣来的。
**修法**：`textlayer.py` 把 `pdftotext -bbox` 转成我们的页级 JSON，`--text-layer` 三档
（`verify` 默认交叉验证 / `only` 只要文字层 / `off` 行为不变）。
**教训**：优化之前先确认「这件事是不是已经被免费做过了」。
我们一直把「扫描书没有文字层」当公理，但用户的书**不全是扫描件**——
这个假设从没被验证过，而验证成本只要 `pdftotext` 跑 5 秒。

### 18. 图片/表格被静默丢弃，靠「碎片段比例」才发现
`DROP_REGIONS` 里没有 figure/image/table，这些区域的行实际被当普通正文**按行流式输出**：
表格被拆成一行一段，图片完全消失（`epub3.build` 的 `files` 只有 xhtml/css/cover）。
僧官实测：1820 段里 **97 段（5.3%）是 ≤6 字碎片**（`唐初` `祠部` `t--` `J.`）。
**发现方式**：不是看代码看出来的，是统计「碎片段占比」统计出来的。
**教训**：静默丢弃不会报错，只会让成书「读起来怪」。需要一个可量化的代理指标
（碎片段比例、汉字数守恒、字符 Counter 差集）才能发现它。
修复后 97→26（1.5%），content 守恒用 `Counter(原始) - Counter(成书)` 验证为 **0 字符丢失**。

### 19. 目录页和表格在几何上分辨不出来
表格判据（多列 + 列间隙 >3 字宽 + 行距紧 + 行尾不收句）**命中了目录页**：
目录也是「左标题 + 右页码」的多列结构。后果极严重：整本目录被合并成两段文字 →
`parse_toc` 拿不到逐行条目 → **整本书失去章节结构，且不报错**。
**修法**：`build()` 里已有 `toc_ids`，几何判据前先整页跳过目录页。不要试图用几何区分，
那个信息在别处已经有了。
另一个同源坑：`PUNCT_END` 含「）」，而表格单元格常以括号收尾（`鸿胪寺（崇玄署）`），
用宽判据会把表切成两半。表格用窄的 `TABLE_END = "。！？；…"`。

### 20. 中断 `all` 后子进程变孤儿，继续跑 20 分钟
`sh()` 用 `subprocess.run(check=True)`，父进程被 Ctrl+C / 被杀时子进程不跟着死。
实测：中断 `all --text-pages 40-140` 后 `pdftoppm` 又跑了 **20 分钟、渲染 425 页**，
一直占文件句柄，`Remove-Item` 报「另一个进程正在使用此文件」，`.tmp-only` 删不掉。
**修法**：`sh()` 捕获中断并 `kill_tree` 子进程。渲染 900 页要十几分钟，用户中途 Ctrl+C 很常见。
**教训**：`check=True` 只管「失败要抛异常」，不管「父进程没了怎么办」。

### 21. 「裁不出图」不是代码坏，是 `pages/` 被 prune 了
上一轮发现僧官 4 个 image region 全部裁剪失败，写成「用 `run-guixun/pages` 验证链路正常」草草收尾。
**根因**：`pages/` 被 `prune` 阶段删了（450 MB/300 页，不进仓库），而 `emit_images` 要读页图。
**修法**：不修代码，用源 PDF 重跑 `render`（350 页 13 分钟）。恢复后 4 张图全部裁出。
**教训**：`report.json` 里 `images.failed_detail` 明写「缺页面图或裁剪失败」——
这句话就是诊断结论，别把它当杂音跳过。**先读报告给的 reason，再怀疑代码。**

### 22. 页顶/页底「书眉残留」规则会吃掉真正文（**已修**，2026-11-16）
`assemble()` 里曾有 `w < 0.55·W and elen ≤ 16 and (y1 < 0.18H or y0 > 0.90H)` 判「书眉」直接丢行。
僧官实测吃掉 **61 行 / 453 汉字**：正文折行后只占半边宽、又恰好落在页顶，就中招。
典型：`基层僧官之自然是没有疑义的。`、`的诏书，更是一个铁证。`

**修之前先证伪了「加文本匹配」这条路**。我把这 61 行逐行与「学到的书眉 + 全部 103 条
目录标题 + 书名」做字符二元组 Dice 相似度：**最高只有 0.60**（次高 0.58），阈值取 0.75
一行都过不了。也就是说在这 61 行上做匹配，**能救回 0 行**——它们全是正文。

**真书眉在上游就已经被删干净了**。边缘带短行的三重拦截实测（僧官/规训/黑格尔）：

| 机制 | 僧官 | 规训 | 黑格尔 |
|---|---|---|---|
| `region=header` 标签（`DROP_REGIONS`） | 150 | 655 | 0 |
| `learn_running_heads` 跨页重复 ≥5 页 | 0 | 0 | 143 |
| `head_band` 自适应带状区 | 3 | 4 | 97 |
| 三重都没拦下 | 87 | 8 | 805 |

没被三重机制拦下的那 87 / 8 / 805 行逐行看过，**都是正文**（其中一部分随后被
`clean_page` 的页码/竖排字规则或 assemble 的标题消费再筛掉，最终真正落到那条
位置判据上的分别是 61 / 1 / 20 行）。所以这条规则在 assemble 层做的不是
「补刀书眉」，是「把已经确认是正文的东西再杀一遍」。

**修法（两处）**：
1. 删掉「窄+短+在边缘」这条位置判据，只留**非文字碎片**守卫：
   `(y1 < 0.18H or y0 > 0.90H) and (not norm(t) or PAGE_NO.match(t) or elen(t) <= 1)`。
   它在本轮的实测价值是拦住 `11` / `°` / `4` 这几个会被粘进上一段末尾的孤立碎片。
2. `learn_running_heads` 的顶部扫描窗口 **0.11H → 0.18H**，配「窄行守门」（顶部且
   `w > 0.55W` 的行不参与学习）。规训的章节书眉落在 y1=10.1%~13.4% 页高，旧窗口
   11 条只学到 2 条，剩下 9 条在 `head_band` 的 0.09 硬上限之下也无处可拦——
   `第二章 断头台的场面第一章` 这种残片就是这么拼进正文的。放宽后学到 11 条。

**效果**：僧官 +629 字符（61 行回归正文）、`notes.linked` 165 与 EPUB 弹窗 165 **首次一致**
（p278 `光绪帝，数年后"转僧录司正印"①。` 那行的锚点恢复）；黑格尔 +199 字符；
**规训逐字节不变**（它的 1 行是 `4`，本就是碎片）。

**教训**：「书眉」是**文本属性**，不是位置属性——但**不等于「丢掉阶段要做文本匹配」**。
正确的分层是：文本匹配放在**学习阶段**（`learn_running_heads`，跨页重复天然是文本证据），
丢弃阶段只认「学到与否」。丢弃阶段再补一次位置判据，补的永远是正文。

### 23. 中间格式没有版本号 → 加了字段就静默误读
页级 JSON 有 4 个写入方（run_ocr / repair / run_layout / textlayer）、6 个读取方。
以前没有 `schema_version`，加文字层来源后下游无法区分「这行是 OCR 认的还是 PDF 自带的」，
`ocr_dir()` 也没法判断该信谁。**修法**：`pagedoc.py` 统一盖 `schema`/`schema_version`/`producer`。
两条硬约束：**老文件必须照常读**（几千个现网 JSON 不能因此跑不动）、
**版本不认识必须拒绝**（不是警告）。
**教训**：契约层只在「有第二个写入方」时才值得建。现在正是那个时候——
如果只有一个写入方，加 schema 就是纯开销。

### 24. 清理路径的两个反向陷阱：会挂死，也会「静默什么都没做」

`kill_tree` 原来只有十几行，看着很稳，实则两个洞（都是静态审阅点出来的，一验就是真的）：

- `subprocess.run(["taskkill", ...], check=False)` **没有 `timeout`**。
  taskkill 卡在 WMI/RPC 上（安全软件拦截 / 远程会话 / RPC 被裁剪的沙箱）时，
  那条「Ctrl+C 收尸」路径**永远回不来**。这比子进程变孤儿更糟：用户既停不掉也退不出。
- `check=False` 且只捕 `OSError`：taskkill 返回非 0（权限不足 / 进程已消失 / **taskkill 不存在**）
  时静默什么都不做。清理代码「什么都没做」和「做失败」在日志上长得一模一样。

**修法**：超时上限 + 非 0 兜底 `proc.kill()` + 返回 0 也要 `wait(timeout)` 确认 → 收尾无条件再
兜底一次。**顺序不能反**：先 `/T` 杀树、再兜底杀直接子进程；反了的话树结构先断，`/T` 就找不到
孙进程了。

**这条测试本身也有坑**：原来拿 `ping -n 60 127.0.0.1` 当靶子进程，在禁用网络栈的沙箱里
ping 会瞬间以 1 退出，测试在调用 `kill_tree` 之前就红了。靶子必须是 `python -c sleep`。

**教训**：清理/收尸代码要同时防「卡住」和「静默失败」——它的两个失败方向恰好相反，
所以既要超时，也要在非 0 时把该做的事补上。还有：**测试的靶子进程不能依赖外部系统工具**，
否则它测的是环境，不是被测代码。

### 25. 属性位的转义只能有一个入口

`epub3.py` 早就有 `esc()`（文本节点，`quote=False`）和 `esc_attr()`（属性位，补 `"`）两个函数，
但 `cover.py` 后来自己写封面时直接 `COVER_XHTML.format(title=title)`——书名里有 `"` 就把
`alt="..."` 提前闭合，`cover.xhtml` 变坏 XML。`&` `<` `>` 同理。

**修法**：`cover.inject` 改用 `epub3.esc_attr()`，不另起一套。

**教训**：同一个语义（「属性值转义」）在项目里只能有一个实现。第二次手写时看着更省事，
一旦分叉，缺席的那一半永远不会被修。**新代码里出现 `"..."` 拼接时，先搜一遍项目里有没有现成的转义函数。**

### 26. 「空样本」是必然事件，别让统计函数先炸

`repair.median_char_width()` 收不到样本时 `statistics.median([])` 抛 `StatisticsError`，
而 `main()` 里那句友好提示（「找不到足够的长行来估计字宽」）**在它之后**——永远执行不到。
空样本的来源很普通：目录页、整页插图、纯扫描件，行宽都不满足「≥10 字且宽 > 0.55W」。

**修法**：返回 `None`，由调用方决定报错还是降级；提示语补上成因。

**教训**：`statistics.*` / `max()` / `[0]` 这类「假设非空」的写法，在数据驱动的流水线里要先问
「空的时候是什么」。调用方已经写了兜底、却被被调方先抛异常截胡，是很常见的假安全感。

### 27. 裸 `open()` 写产物：句柄和原子性一起丢

`disagree.py` 三处（`json.dump(obj, open(...))` ×2 + `open(...).write()` ×1）、
`audit.py` 两处、`cmp_ocr.py` 一处。`jsonio.py` 的存在理由正是这两条，但新脚本一直在绕开它。

**修法**：全部改走 `jsonio.write` / `jsonio.write_text`；页级 JSON 走 `pagedoc.write`。
并加了一条**通用断言**锁住脚本源码（不许出现 `json.dump(`、不许 `= open(... , "w")`）。

**教训**：写了工具函数不等于用上了。**只在文档里说「统一走 jsonio」是无效约定**，
得有一条能自动跑的断言。改这种纯写法改动时，顺手比一次产物 SHA256——一致就等于证明
「只换了写法」，不一致说明顺手改坏了逻辑。

### 28. 同一个常量连写两遍

`apply_decisions.py` 里 `LEGACY_TABLE = ...` 写了两行。行为上无害（值一样），但这是
「早晚会有一次只改了其中一处」的种子。用 `^LEGACY_TABLE\s*=` 计数断言锁成 1 次。
### 29. 同一页有两套完整文字：逐对去重永远判不出来

《拉康式主体》（上海文艺 2024）的文字层里，**每页都同时有**「16.5pt 的整行框」
和「11pt 的逐字框」两套完整文本。`pdftotext -bbox` 两套都吐。

`dedupe_words` 判不出来，原因值得记住：它比的是**相邻**两个 word。
这里两套小框是同基线并列的（「回」「到」「精」都在 y1=105.8），相邻小框文本各不
相同；整行大框夹在这串后面，与紧邻的小框又不等长。**任何一对都不满足判据。**

判据要换维度：不是「两个框相等」，而是「**一行里有两簇字高**」+「**两条候选的 x
跨度几乎完全重合**」。两个都是几何判据，跟文本无关。

两级缺一不可：只拆不合并 CJK 265,249（没变），只合并不拆 167,053（+13.7%），
拆+合并 151,445（+3.1%，真实值 146,866）。**「我加了规则」不等于「问题解决了」**，
必须拿真实值对账。

### 30. 打印用户文本 = 一条能让整轮流程归零的路径

Windows 子进程 stdout 默认 **GBK**。`print()` 里只要有一个 GBK 编不进去的字符，
就是 `UnicodeEncodeError`，脚本当场死。

这本书正文有 Ü É ç ∅ ∀ ∃ S₁ S₂（全书 155 行）。`repair.py` 崩在打印上，
而它**已经写完 129/310 页**——退出码 1 让 `bookflow.py all` 判定整个阶段失败，
剩下 181 页一个都没写。**业务全对，只是话说不出口，结果等于全错。**

所以 stdio 编码不能当「调用方的责任」。全项目一份 `stdio.utf8_stdio()`，
14 个脚本入口都调，**并用测试扫源码**（少一个就红）——约定靠人记，测试靠机器查。

`errors="replace"` 是刻意的第二道保险：显示不了就退化成 `?`，别让进程死。

### 31. 正则范围宽于真实字符集 = 定时炸弹

`layout.NOTE_HEAD` 写的是 `[\u2070-\u209c]`，看名字像「上标数字」，
实际这个区间里有**下标** ₀-₉（U+2080-2089）、上标 i（U+2071）、
上标运算符 ⁺⁻⁼⁽⁾（U+207A-207E）——全不是数字。

旧实现用 `表.index(s)`，s 不在表里就抛 ValueError。拉康正文的 S₁ 一出现，
整本 `make_md` 直接失败。**一个正区间写成「范围」而不是「字符集」，就埋下了这颗雷。**

另一半点：表里**写了** ¹²³（U+00B9/B2/B3），但区间判断 `0x2070 <= o <= 0x209C`
把它们挡在外面——**表里有、判断走不到**，同样是 bug。查表就查表，别再用区间二次筛。

### 32. 「看起来像页码」和「位置在右边」是两件事

目录页码判据一直是几何的：「页码列在页面右半侧（x0 > 0.5W）」+「页码前有引导点」。
《拉康式主体》的目录页是「总序 /III」「…爱、欲望、享乐 /113」——**整行一个框、
x0 在版心左边界、没有引导点**，两条判据全不成立。

后果不是「页码丢了」而是**整页结构崩掉**：每条都被当成「没有页码的折行」，
一层层拼到下一条上，13 条目录压成 12 条怪物，命中 0，成书没有章节。

新判据是纯文本的：「行尾是斜杠+数字 / 斜杠+罗马数字」。关键是那条**负向断言**
「斜杠前不能紧贴数字」——不然目录页上「比例 3/4」会把 4 当页码。
**这条是测试逼出来的，不是一开始就想到的。**
### 33. 「有书签就直接搬」是错的：书签可能只是导航跳板

PDF 的 `/Outlines` 是数字文本：标题一个字不错、页码精确、层级就是嵌套深度。
《拉康式主体》书签 23 条，比 OCR 目录页解析出来的还好（后者 8 条没落到正文）。

但**不能无条件优先**。本地 111 个 PDF 实测 59 个带书签，其中相当一部分只有
「封面/书名/正文」这种跳板：

| 书 | 书签 | 目录页解析 |
|---|---|---|
| 拉康式主体 | 23 条 | 23 条（8 条未命中） |
| 规训与惩罚 | 17 条（多「前言」） | 16 条 |
| 中国僧官制度史 | **3 条** | **103 条** |

判据是「**书签至少和目录页一样细**」，不是「有书签就用书签」。
第一版写成后者，僧官那本 103 条目录直接变 3 条。

另一条：书签标题要**原样用**，别过 `unify_title`。那个函数的语义是
「目录条目是 OCR 出来的、拿正文补齐」，对数字文本只会越补越差
（「附录1：无意识语言」→「附录 11：无意识语言: 无意识语言」）。

### 34. 标题里的「部分」是一个词，别硬插分隔空格

`assemble` 有条规则把「第X部」和后面内容用全角空格隔开，因为 OCR 常把
「第一章犯人的肉体」黏成一串。但「部分」本身就是词：
**「第1部分结构：异化与他者」被插成「第1部　分结构：异化与他者」**。

这条规则还有第二个 bug：`[讲章节篇卷部编]` 匹配到「部」就停，「分」被留给
分隔符——所以即便走目录页也会拆。改成 `(?:部分?|[讲章节篇卷部编])`。
**两个 bug 同一个根因：正则按"字符类"写，而这里是"词"。**

书签条目干脆整个绕过这条规则（见上一条）。

### 35. 图形区只在 image/figure 里，公式和图表会直接漏进正文

版面分析输出的 `display_formula` / `chart` **既不在 `DROP_REGIONS` 也不在
`FIG_REGIONS`**——两条路都不走，于是它们的 OCR 结果原样进正文：
`tt+1 情况B`、`二：L z 情 A`、`父亲 3x<t>x Sj`。

把它们并进 `FIG_REGIONS` 走裁图。**为什么不并进 `DROP_REGIONS`**：直接删
会让成书里凭空空一块，读者不知道原处原本有什么；裁图不丢信息，留在正文里才丢。

### 36. 判据要挑「两侧必然一真一假」的那个信号

叠字图层选哪一条，直觉是「字数多的信息全」。但两套文字**字符数常常相同**
（`Klein` 5 字 vs `K le in` 6 个字符），光比字数在 285 页里挑错一半。

真正必然分对错的是**拉丁碎词**：整行那套不会把 `Klein` 切成 `K le in`。
实测拿 OCR 当真值比了五种排序键（310 页，编辑距离）：

| 排序键 | 编辑距离 | 碎词 |
|---|---|---|
| (字数, 字高) | 18595 | 563 |
| (非空白字数, 字高) | 17715 | 251 |
| **(-碎词, 非空白字数, -空格, 字高)** | **17709** | **162** |

注意第二级必须是**去掉空格**的字数：不然 `K le in` 多出的 4 个空格会被当成
「信息更多」，正好选错。

### 37. 章标题常常就是那一章的书眉，按文本删会把整章删没

`learn_running_heads` 学「跨页重复的版式文本」。但「附录2 追踪原因」「索引」
这种章标题**本身就是该章的书眉**，于是这一章唯一的标题被当版式删掉，
成书里该章凭空消失（拉康 p266、p288）。

修法与已有的 header 免责同源：**位置证据优先于文本证据**——书眉在页眉带里、
章标题不在；再要求区域标签是标题区。三条同时成立才留。

### 38. 「读不出来」和「读出来是假的」要分开处理

表格乱码（表10.1 变成 `·F　F 第3行　T`）不是 OCR 错，是**文字层把单元格框
拆散了**；同一张表的 OCR 结果反而是完全正确的。

不去猜哪一侧对（那需要逐表人工判断），而是加一条**可读性判据**：
视觉行的列数是否一致。真表格每行同样几列，列数乱跳说明被拆碎或认残了。

实测门槛 `一致率 ≥ 0.7 且众数列数 ≥ 2`：真表格 0.67~1.00、被打散的框图
0.25~0.43，中间几乎没有样本。**判据要落在分布的空白处，不是分布里。**

不可读的走裁图，可读的仍出文字——「读不出来」的兜底是图，
「读出来是假的」的兜底也只能是图。

### 39. 裁决「定位不到」的条目，补完 y0 仍然回填不上（verdict=C 被 A 校验挡住）

`decisions.from_audit` 对词被行长切断的条目（p-272「介|人」、p-287「人|狱」）只能落成
`verdict=?` + `y0=null`，因为 audit 找的是**行内子串**。人翻原书把 y0 和整行补上、
改成 `verdict=C` 之后，`apply_decisions.plan()` 仍要求「当前行 == A」才敢改——
而这类条目 `A` 是空的，于是**照样判 missing**（实测 `missing 2`，退出码 0，看着像成功）。

**修法**：对 `C` 且 `A` 为空放行（人看着原书给的整行本身就是权威）；`A/B` 不放宽，
它们靠 `A` 做「别改错行」的校验。

**教训**：`A` 在这里同时承担「原文快照」和「防改错行的校验基准」两个职责。
只要有一个分支的 `A` 是空的，就必须显式决定「谁替它做校验」，否则会静默跳到 missing。

### 40. 跨行词到底改哪一行，看切分后的两半，不是固定规则

`介人` 在 p-272 是「…言语介」+「人可怕…」（错在**后半截** → 改下一行）；
`人狱` 在 p-287 是「…刚刚人」+「狱还是…」（错在**前半截** → 改本行）。

初版一律改第一行，结果 p-272 把对的「介」改成了「入」。第二版改判「错字在前半截就改本行」，
又把 p-287 判对、p-272 判错——因为比较的是 `head != right[:k]` 而不是 `tail != right[k:]`。
**判据只有一条**：按每一种切分拆成 (head, tail)，哪一边与 right 对应的那一边不等，就改哪一行；
两半都等 → 词本身没坏，只是被切开了。

**教训**：行级裁决是**整行覆盖**，改错行等于把两行内容互换。这种错不报错，
只是让成书里出现一句从别处搬来的话。

### 41. `verdict=B` 在给人看的表里必须整行，不能只给「差异片段」

`apply_decisions.desired_text` 对 B 是**整行覆盖**（不是替换差异段），这是修掉
「多差异段静默跳过」的方式。所以任何给人填表的中间层都必须：
① 让人看到足够写整行的上下文（默认 64 字）；② **只把整行回写**。
把片段当整行写下去，会静默删掉这一行剩下的内容。

### 42. `is_tiered()` 不能把 manifest.json 算进判定（否则 flat 目录会「凭空消失」）

判据最初写成「有 `manifest.json` **或** 有 `work/` `report/` `review/`」。看着很自然，
实际后果是：在 flat 目录（`pages/ out/`）上跑**任何一个阶段**都会写下 manifest →
下一次调用立刻把整棵树判成 tiered → 所有路径改解析到 `work/` `report/`，而那里是空的。

表现是「跑一次 `md` 之后 `run-lacan/out/` 整个消失」，而**每一步的退出码都是 0**。
比丢文件更难查，因为没有任何一处报错。

**规矩**：布局判定只看目录，manifest 一律写在 run 根、两种布局同位置，不参与判定。

### 43. 页图名必须容忍补零差异，而且三处要同一个口径

`pdftoppm` 按**页数**决定补零位数：9 页的书出 `p-1.png`，310 页的书出 `p-001.png`。
而页级 JSON 一律按 `p-001.png` 命名。三个模块各自 `os.path.join(pages, name)`，于是各自踩：

| 模块 | 后果 | 是否报错 |
|---|---|---|
| `make_review.py` | `FileNotFoundError`，整轮 `all` 在**最后一步**失败 | 报错 |
| `run_layout.py` | 全部「跳过（缺页面图）」，region 一个都没打上 | **退出码 0** |
| `bookflow.py` 的 `stage_layout_guarded` | 用文件名交集判「对不上」，在 <100 页的书上**永远是空集** → 连 `run_layout` 都没被调用 | **退出码 0** |

最后一处最阴：守卫本身是为了防止「17 页小册子整本跳过」而写的，结果它的判据
在**页数小于 100 的书**上恒为假——同一个 bug 被修了一次，留下了另一半。
**按页号比，不按文件名比**；三处共用同一条 `_page_image()` 规则。

### 44. `runs` 不能进发现流程的 `_SKIP` 列表

`runs/` 在 `list_ids()` 里有专门分支（只认 `runs/<id>` 这一层）。一旦把它也列进 `_SKIP`，
`if n in _SKIP: continue` 会先命中，那个分支永远走不到。
表现：新书跑完了却**不出现在界面上**；而接口 404 又被前端兜底成一张空卡片，
于是看起来像「明明跑完了却显示全部未跑」。

**教训**：跳过名单和特判分支不能同时存在——两者谁先命中没人会记得。

### 45. 前端的多段 run id 必须由「布局约定」判定，不能靠「猜最长前缀」

新书的 run id 是 `runs/<book-id>`（两段）。后端最初用「试最长前缀」解析：
先试 `run-a/report` 再看 `run-a`。结果 `/api/runs/run-a/report` 被解析成 run id `run-a/report`——
因为 tiered 布局下 `<run>/report` **本身就是个目录**，`resolve()` 看它像工作目录就放行了。
实测：`report` 接口一律 404。

**规矩**：只在第一段**恰好是** `runs` 时才按两段解析。判据来自布局约定，
不能来自「目录长得像」。前端的 hash 路由同理：末段是视图名（`triage`/`inspect`）才吃掉它，
否则整串都算 id。

### 46. `apply_decisions --src` 与 `--decisions` 也要走 `paths.py`

分层布局把 OCR 目录搬到 `work/` 下、裁决表搬到 `review/` 下，而 `apply_decisions.py` 里
还写着 `os.path.join(a.work, a.src)` 和 `os.path.join(work, "out", "decisions.json")`。
结果是**回填完全跑不起来**：报「找不到 OCR 目录」/「找不到裁决表」，退出码 1，
而 WebUI 那边只看到「作业失败」，看不出是路径口径问题。

**教训**：加一种布局就要把所有 `os.path.join(<work>, ...)` 找一遍——
`grep -n 'a.work,' *.py` 是那条命令。漏一处就有一条路径只在**新书**上出错，
而旧书测试全绿。

### 47. 打样模式（`--limit-pages`）必须在日志里喊清楚

`--text-pages` 时代就踩过：局部页跑全流程会产出一本**残书**，而 `audit`/`make_review`
还要按全书页名去 `pages/` 找图，必然找不到。`--limit-pages` 是同一类参数（给 WebUI 的打样预设用），
所以它一进 `stage_render` 就打醒目告警。

**规矩**：任何「只为预览、产出不完整」的参数，必须在入口打印「产出的是残书，不要拿去交付」。
### 48. 后端 `diff[]` 只带差异片段，不带相同文字

契约里 `diff[].op/i1/i2/j1/j2` 给的是**差异区间在整行里的下标**，`a` / `b` 只是那一段的字。
第一版校对页直接遍历 `diff[]` 渲染，于是整整一行只显示出被换掉的那个字：
A 候选显示「已」，B 候选显示「己」，前后文全没了。

**不是后端的问题**，是我误把它当成了「整行切段」。正确用法是把它当**区间标注**套在全文上：
按 `i1/i2`（A 侧）、`j1/j2`（B 侧）切 `A` / `B` 原文，中间没被标注的部分原样输出。

### 49. `"?"` 是真值：按 `verdict` 判「做过没有」会把所有待办算成已完成

后端把**没判过**和**明确跳过**都写成 `verdict: "?"`，区别在 `status`：
`pending` = 没判过，其它 = 判过（明确跳过）。
前端写成 `if (item.verdict)` 就直接失效——`"?"` 是 truthy，于是 run-lacan 的 2825 条里
2380 条待校对全被算成已校对，顶栏显示「已校对 2380 / 2380」，进度条满格。
**表现是「活还没干，界面说干完了」**，比显示不对更坏。

### 50. 进度条要按**全书**算，不能按当前加载的子集算

校对页默认只拉 `only=eyes` 的 999 条（另有 1826 条纯标点空白差异）。进度按这 999 条算，
就显示「已校对 999 / 999」——而全书 2380 条待校对。用户会以为做完了。
**凡是「总数」都要用后端给的 `total` / `pending`**，子集只用于列表浏览。

### 51. 差异高亮最后**一点底色也没留**：加粗 + 划线就够

走过三段弯路，值得完整记下来，因为每一段当时看着都对：

1. **橙底 `#ffb347` + 棕字 `#8a5a00`**：WCAG 只有 **3.33:1**（正文阈值 4.5:1）。
   橙色本身亮，浅色文字压上去必糊。而这里要看的偏偏是「已 / 己」这种一笔之差。
2. **浅琥珀底 `#fdf0d0` + 深棕字 `#8a5a00`**：5.24:1 达标，看着「修好了」。
   但放大截图后发现两个新问题：底色在字周围铺一圈，**字形边缘被色块吃掉**；
   一行里出现两三处差异时，视线被色块牵走，真正要看的笔画没人看。
3. **现在：无底色 + 700 字重 + 2px 划线（`text-underline-offset: 3px`）**，
   文字色沿用正文色。整行只有黑与灰两级，没有需要额外解释的色相。

两个实现细节：
- `offset` 用 3px 不是 2px。汉字下缘本来就画到基线以下，2px 时划线贴住笔画，
  实测在「已」上看起来像一坨黑边，反而更难认。
- **不要用 `text-decoration-thickness` 之外的东西去模拟加粗**（比如多层 text-shadow），
  那会在 14px 下把字晕开。

**核实步骤**：放大截图（`--force-device-scale-factor=2` 再裁图放大）看真实像素，
别看设计稿，也别只看对比度数值——3.33:1 和 5.24:1 两版在数值上差别很大，
但两版失败的真实原因都是「底色占了字的空间」，而这在任何对比度公式里都不体现。

### 52. CLI 传参给 Python 函数时，`None` 会覆盖掉默认值

`crop_png(..., context=5)` 加了个默认值，路由里写 `crop_png(root, page, y0, h, context=q.get("context"))`，
不带 `context` 时 `q.get` 返回 `None`，默认值 5 被直接覆盖 → 带上下文的裁图**静默退回单行**。
表现是「明明改了代码，图还是那条窄条」，而且没有任何报错。
**规矩**：路由层不要无脑透传 `q.get(...)`，缺省值要么过滤掉、要么用 `**kw` 只在真有值时传。

### 53. 一次「看起来只是问号」的提问，先照字面理解会做错事

用户问「候选栏的需要修改的字不要用同色调，背景用橙色，字体用棕色，你觉得这能看清吗」——
这是**在质问现状**，不是配色指令。我按指令做了一版橙底棕字（3.33:1，真的看不清），
用户回：「不是指令而是对现状的质问，简单的加黑就可以了」。
**教训**：句子里带「你觉得…吗」时，先回答那个问题，再决定改不改；不要跳过判断直接执行。

### 54. 未跑阶段必须给按钮，跑不了的必须把理由写在行内

《中国僧官制度史》的「核对」在界面上是一行**死行**：没有按钮、没有理由。
两个原因叠在一起，第二个更值得记：

1. `progress.js` 只在 `status !== "missing"` 时画按钮——所以所有未跑阶段都点不了；
2. 这本书的「核对」**本来就永远跑不了**：文字层每页平均 10 个汉字，
   `_textlayer.meta` 判 `usable=false`，`ocr_text/` 里一页 JSON 都没有；
   而 `stage_verify` 要文字层与 OCR 两侧逐行对账，缺 A 侧必然 `sys.exit`。

**先补按钮会更糟**：点下去弹一行「verify 需要先跑 textlayer 阶段」，用户只会去重跑
textlayer——而那一步跑了也还是 10 汉字/页。**理由必须写在行内**
（`.pg-stage-why`），不能只放 `title` 悬停，悬停看不见等于没有。

判据在 `runs.stage_runnable()`，三条纪律：
- 纯文件系统检查。它被 `/api/state` 对**每本书**调用，读大 JSON 或跑子进程会拖慢整页。
- **绝不抛异常**：它站在渲染路径上，一个列不出目录的权限问题没有资格让整页报错。
- 用 `paths.work_dir()` 这类函数定位，不写死 `"work/"`——
  `run_root` 可能是 tiered 的 `runs/<id>`，也可能是旧 flat 目录或仓库根。

### 55. 空态 / 错误态放进 CSS Grid 容器，只占第一列

`.pr-body` 是三栏 `grid-template-columns: 200px minmax(0,1fr) 320px`。
加载完成但没数据时，代码 `clear(body)` 后直接 append 一个空态 div——
它成了 grid 的**第一个格**，被挤进 200px 的分组栏，标题竖排成一行三个字。

修法是给空态包一层 `.pr-emptywrap { grid-column: 1 / -1 }`。
同一类错误的通式：**往 grid/flex 容器里换内容时，新内容要显式声明跨度**，
不要指望它「自然占满」——grid 的默认行为是占一格，不是占一行。

顺带修了顶栏文案：`total === 0` 时原来显示「全书已校对完」，
而真相是「还没有校对清单」。**0/0 不能说成 100%**。

### 56. 合并测试用例时，用「执行了几次断言」对账，不要用「写了多少个用例」

450 个用例里 293 个只有 ≤2 条断言，「一个类一个方法」的散装类一大片。
按判据合并成 `subTest` 参数化之后变成 303 个用例，但**实际执行的断言从 2473
次变成 2483 次**——验证能力不减反增。

两个统计口径都要注意：
- 数**语句行数**不够：一个 `assertEqual` 放进 for 循环里执行 6 次，语句还是 1 行。
- 数**用例个数**更不够：这次合并的正是"个数"。

可靠做法是在运行期给 `TestCase` 的所有 `assert*` 打补丁计数（`startTest` 里逐个
setattr 包一层），再逐个类对账。合并过程中就是靠这个发现三处「反例其实是绿的」：
1. `cover.inject` 对已存在 `cover.xhtml` 的包是**跳过而非覆盖**，同一个 epub
   复用注入第二个书名时安静地什么都没做，断言读到的是上一个书名；
2. `TestLayoutGuard` 在一个用例里 seed 两轮（正例、反例），上一轮的页图残留让
   **反例的前提根本没成立**——原来两个独立方法各跑一次 setUp，问题被掩盖；
3. `epub3.validate(out)` 写在 `TemporaryDirectory` 的 with 块外，临时文件已删。
