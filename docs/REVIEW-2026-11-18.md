# BookFlow 项目审阅（2026-11-18）

审阅对象是当前工作区，包含尚未提交的 `make_table.py`、跨行定位和裁决回填改动。
本次只增加审阅文档和入口链接，没有修改功能代码或已有运行产物。

结论：发现 **2 个 P1、4 个 P2**。主要风险集中在已有产物的复用、人工裁决的保留，
以及 Markdown 表格导入。以下每项都用临时样本验证过相关执行路径；没有把推测或
执行环境导致的测试失败列为代码缺陷。

## 1. [P1] 重跑验证覆盖人工裁决，只保留了旧 status

位置：`bookflow.py:772–786`，调用方 `stage_verify()` 和 `stage_decisions()` 的 `--merge` 分支。

`_merge_keep_status()` 先执行 `dec.merge(old_doc, new_doc)`，同 key 的新机器候选会整条
覆盖旧条目。后续只恢复 `status`，没有恢复人工填写的 `verdict`、`replacement`、`note`。
因此重跑 `verify`（包括默认 `all` 流程）会丢失已保存的人工判断。

复现：旧条目为 `verdict=C, replacement="人工确认", status=applied`；新候选在同一
`page@y0` 上给出 `verdict=B`。调用 `_merge_keep_status(old, new)` 的实际结果：

```json
{"verdict": "B", "replacement": null, "status": "applied"}
```

结果同时存在两种错误：人工整行替换消失，机器新建议却被标成已应用。即使尚未执行
回填，唯一保存人工裁决的文件也已经被覆盖。

建议：刷新候选时保留已有裁决内容，新增候选单独合入；原文 A/B 发生变化时明确保留
旧判断并提示核对，不能把旧 `applied` 状态直接挂到新内容上。补充人工 C 和人工否决 A
在重跑验证后仍保留的回归测试。

## 2. [P1] 非空目录被当成完整产物，中断续跑可能缺页出书

位置：`bookflow.py:625–627`、`bookflow.py:1005–1013`；相关路径为 `run_layout.py:115–123`。

渲染阶段只要 `pages/` 非空就跳过。渲染途中中断后，目录可能只有前若干页，续跑时不会
补齐。下游 OCR 按现存 PNG 枚举，Markdown 按现存 JSON 枚举，无法发现从未生成的页。
`--text-layer off` 下也没有文字层覆盖率检查来兜底。

另一个相同后果的入口是选源：`ocr_dir()` 只检查目录中有没有 JSON，不检查覆盖页。
如果 `ocr_layout/` 只成功生成一页，它仍优先于拥有全书的 `ocr_fix/`。版面分析缺少
某张图时会直接跳过该页并正常退出，因此这不仅发生在手动误配目录时。

临时样本结果：

```text
pages/ 仅有 p-001.png，force=False：stage_render() 没有调用渲染命令
ocr_fix/ 有第 1、2 页，ocr_layout/ 只有第 1 页：选中 ocr_layout，页数为 1
```

第一项验证了渲染的跳过分支，第二项验证了实际选源结果；本次未通过 GPU OCR 重跑
整本书。按当前枚举逻辑，缺失的尾页或中间页不会进入后续正文输入。

建议：用 PDF 页数和实际页号判断渲染是否完整；选择下游源时对照所需页集合。
未完成的目录应补齐、退回完整来源或明确失败，不能因非空就视为可用。这里用普通
页号集合比较和中断续跑测试即可，不需要额外 hash 或冻结机制。

## 3. [P2] layout 避免读自己时，绕过了文字层模式过滤

位置：`bookflow.py:1105–1110`。

`ocr_dir()` 原本会经 `active_dirs(a)` 处理 `--text-layer off`。但当它选中已有
`ocr_layout/` 后，`stage_layout()` 改用未过滤的 `OCR_DIRS[1:]` 查找上游，重新把
`ocr_text/` 放回竞争列表。

复现目录：`ocr_layout/`、`ocr_text/`、`ocr_fix/` 都有页 JSON，未指定 `--ocr-src`。
调用 `stage_layout()`，参数为 `text_layer="off", force=True`，截获传给
`run_layout.py` 的命令，得到：

```text
--src <work>/ocr_text
```

用户要求回到 OCR 来源，实际却把文字层重新写进 `ocr_layout/`，后续出书仍然使用它。

建议：上游重选复用 `active_dirs(a)`，排除目标目录后再选择，不另写一套未过滤顺序。
测试应覆盖“已有 layout 产物 + off + force”的阶段调用，而不只测试过滤函数本身。

## 4. [P2] 跨行候选绕过同一行的归并，生成重复主键

位置：`decisions.py:313–329`，对照普通候选的 `grouped` 分支。

普通 audit 命中会按 `page@y0` 汇总同一行的多处建议；新增跨行命中直接 append 到
`out`，没有参与汇总。当同一行既有行内错词又有行尾跨行错词时，生成的裁决表含两个
同 key 条目。后续 `apply_decisions` 拒绝整份文件，人工表导入也会被校验拦下。

复现页文本：

```text
y0=100：错误介人和刚刚人
y0=180：狱开始
```

audit 输入两项：`介人→介入`、`人狱→入狱`。`from_audit()` 实际输出：

```text
keys = ['p-001.png@100', 'p-001.png@100']
validate = ['decisions[1] key 重复：p-001.png@100']
```

建议：跨行与行内建议共用按行归并流程，叠加该行的替换并保留各自说明；遇到建议
冲突时交人工处理。补充“一条跨行建议与一条行内建议落到同一行”的测试。

## 5. [P2] 表格多出列时不报错，整行替换文本被静默截断

位置：`make_table.py:351–357`。

解析器只拒绝列数不足，列数多于 7 时照常读取前 7 列。如果人在 C 的替换整行里输入
未转义的 `|`，后半段会被当成额外列并忽略。由于回填采用整行覆盖，这会删除正文。

直接调用 `parse()`：

```markdown
| `p-001.png@100` | p-001 | 原文 | 建议 | 100 | C | 左边|右边 |
```

实际结果：

```text
errors = []
replacement = '左边'
```

建议：要求列数恰好等于表头列数，多列同样拒绝导入，并提示将字面竖线写成 `\|`。
补充 C 替换列包含未转义竖线、导入失败且原 JSON 不变的测试。

## 6. [P2] 未定位条目的填表提示要求留空坐标，照做无法回填

位置：`make_table.py:298–305`，相关检查 `apply_decisions.py:210–215`。

渲染出的操作说明让人填 C 和替换整行，并明确要求“行 y0 留空”。但未定位条目原本
没有 y0，回填端必须先按 y0 找到行，才能执行新增的“C 且无 A”整行覆盖分支。

复现：渲染 `y0=None` 的条目，按提示只填 C 和替换文本，再 parse、merge、plan。
实际结果：

```text
parse_errors = []
validate = []
plan.kind = 'missing'
plan.reason = '裁决没有 y0（未定位）'
```

导入看起来成功，正文却不会改。当前 `apply_decisions` 对 missing 仍返回 0，继续
跑后续阶段也无法使这个条目生效。

建议：明确要求未定位条目补入实际行 y0，导入时对需要回填但仍缺坐标的 C 条目给出
具体错误。测试从渲染出的说明对应操作走到 `plan.kind=apply`，不能只测试手动传入
y0 后的 key 重算。
