# bookflow WebUI 设计规范（浅色 · 现代简洁）

> 本文件是**界面层的唯一设计依据**。后端契约见 [webui/API.md](../webui/API.md)，
> 布局与目录见 [LAYOUT.md](LAYOUT.md)。本文件只回答「长什么样、叫什么」。

## 0. 为什么有这一版

v1 界面是深色、高密度、术语混杂的：叫「裁决台」「流水线看板」「成书检视」，
沿用了内部实现的名词。用的人是在给一本书做校对，不是在调试流水线。
所以这一版做三件事：

1. **浅色**——长时间看文字与页面图，深色背景让字形对比失真。
2. **术语换成行业词**——校对就是校对，不要叫裁决。
3. **校对页重排**——证据图（原书页面）是判断的唯一依据，它必须占最大面积；
   判定按钮是最高频操作，它必须大而清晰、可盲操。

## 1. 术语映射（强制，含路由）

| 旧 | 新 | 路由 |
|---|---|---|
| 运行列表 / runs | **任务列表** | `#/tasks` |
| 新建任务 / setup | **新建任务** | `#/new` |

| 裁决台 / 裁决 | **校对** | `#/task/:id/proofread` |
| 裁决表 | **校对清单** | — |
| 成书检视 | **成品** | `#/task/:id/output` |
| 预设 / preset | **方案** | — |
| 审批 / approve | **确认** | — |
| 待裁决 | **待校对** | — |
| job / 作业 | **执行**（后台进程） | — |

**只改显示层与前端路由。** 后端 API 的 JSON 字段名（`pending_decisions`、
`verdict`、`preset` 等）与 HTTP 路径一律不动 —— 契约冻结在 webui/API.md。

## 2. 配色令牌

浅色、低饱和、单一强调色。所有颜色只在这里定义，组件里不许写字面色值。

```css
:root {
  /* 底层 */
  --bg:            #f6f7f9;   /* 页面背景，近白带一点灰蓝 */
  --surface:       #ffffff;   /* 卡片 */
  --surface-2:     #fafbfc;   /* 次级区域、表头、条纹 */
  --surface-hover: #f2f4f7;

  /* 线 */
  --border:        #e6e8ec;
  --border-strong: #d3d7de;
  --border-focus:  #93b4f7;

  /* 文字（三级，不要更多） */
  --fg:            #1c2024;   /* 正文 */
  --fg-muted:      #5b6470;   /* 次要说明 */
  --fg-faint:      #8a929e;   /* 元信息 */

  /* 强调色：一个蓝，克制使用 */
  --accent:        #2f6bf0;
  --accent-hover:  #2159d8;
  --accent-fg:     #ffffff;
  --accent-soft:   #eef3ff;   /* 选中底、徽标底 */

  /* 语义色 */
  --ok:            #1a9d55;  --ok-soft:     #e9f8f0;
  --warn:          #cf7d0a;  --warn-soft:   #fdf4e3;
  --danger:        #d64545;  --danger-soft: #fdeeee;
  --neutral:       #78828f;  --neutral-soft:#f0f2f5;

  /* 差异高亮**故意不给颜色令牌**，理由见 §5.3。 */

  /* 形状与投影 */
  --radius-sm: 6px;
  --radius:    8px;
  --radius-lg: 12px;
  --shadow-sm: 0 1px 2px rgba(16,24,40,.05);
  --shadow:    0 1px 3px rgba(16,24,40,.07), 0 8px 24px -8px rgba(16,24,40,.10);
  --shadow-lg: 0 4px 12px rgba(16,24,40,.10), 0 24px 48px -16px rgba(16,24,40,.18);

  /* 排版 */
  --sans: "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", system-ui, sans-serif;
  --mono: "Cascadia Mono", Consolas, monospace;
  --fs-xs: 12px; --fs-sm: 13px; --fs: 14px; --fs-lg: 16px;
  --fs-xl: 20px; --fs-2xl: 26px;

  /* 间距（4 的倍数） */
  --sp-1: 4px; --sp-2: 8px; --sp-3: 12px; --sp-4: 16px;
  --sp-5: 24px; --sp-6: 32px; --sp-7: 48px;

  --topbar-h: 56px;
}
```

**用色纪律**：`--accent` 只用于主按钮、当前导航、选中态、进度条填充。
一屏之内强调色面积不超过 10%。

## 3. 排版与密度

- 正文 `--fs`（14px）/ 行高 1.55。表格、日志、元信息用 `--fs-sm`。
- 页面标题 `--fs-xl`（20px）半粗（600），不用 700。
- 卡片圆角 `--radius-lg`，内边距 `--sp-5`。卡片之间间距 `--sp-4`。
- 交付物、路径、页码、文件名一律 `--mono` + `--fg-faint`。
- 所有按钮最小高度 32px；校对页的判定按钮 44px。
- **禁止**：渐变背景、发光阴影、全大写英文标签、彩色边框堆叠。

## 4. 五个视图

### 4.1 任务列表 `#/tasks`

顶栏下方一个工具条：左侧「共 N 个任务 · 待校对合计 M 条 · 已出成品 K 本」，
右侧搜索框（按书名 / id 过滤）。

卡片网格（`minmax(360px, 1fr)`），每张卡片：

    ┌────────────────────────────────────────────┐
    │ 拉康式主体：在语言与享乐之间       [已出成品]│
    │ 310 页 · 单层布局                     lacan │
    │ ●●●●●●●○○○  7/9 阶段                      │
    │ 待校对 2,380 条                             │
    │                        [打开] [校对] [成品] │
    └────────────────────────────────────────────┘

- 阶段点：圆形，完成=实心 `--ok`，进行中=`--accent` 带脉冲，未跑=空心 `--border-strong`。
- 「待校对 N 条」用 `--warn` 徽标；0 条时显示灰色「无待校对」。

### 4.2 新建任务 `#/new`

三步向导（步骤指示器在顶部）：
1. **来源**：拖拽或点击上传 PDF；已上传的 `input/*/source.pdf` 也可选。显示页数。
2. **书目信息 + 方案**：书名/作者/出版社三个输入框；三张方案卡片
   （古籍与纯扫描本 / 现代学术排版 / 前 20 页极速打样），选中卡片有 `--accent` 边框 +
   `--accent-soft` 底。高级参数可折叠展开。
3. **确认**：把 `resolved` 参数**逐项列出成表格**（键 / 值 / 说明），
   这是审批闸门 —— 人核对后按「开始处理」。

### 4.3 处理进度 `#/task/:id`

两栏：左 = 阶段纵向时间线（9 项，每项有状态图标、耗时、件数、说明），
右 = 日志面板（`--mono`，自动滚底，可按阶段过滤）。

顶部：书名 + 整体进度条 + 当前阶段名 + 已用时间 + 「中断执行」按钮（危险色描边）。
阶段状态色：完成 `--ok`、运行中 `--accent` 带旋转图标、降级 `--warn`、
失败 `--danger`、跳过 `--neutral`、未跑 空心。

**每一行都必须有操作入口**，不存在「看着有、点不了」的行：

| 行的状态 | 右侧按钮 | 点了会怎样 |
|---|---|---|
| 已跑过（ok / degraded / failed / skipped） | 「重跑」 | 只重跑这一阶段，覆盖它的产物（二次确认） |
| 未跑 + 前置条件齐全 | 「运行」 | 只跑这一阶段（二次确认） |
| 未跑 + 前置条件不齐 | 「运行」（禁用） | 按钮下方用 `.pg-stage-why` 直接写出**为什么跑不了** |

第三种是实测逼出来的：《中国僧官制度史》的「核对」永远跑不了——它的文字层
每页平均 10 个汉字，`_textlayer.meta` 判 `usable=false`，而 `verify` 需要文字层
与 OCR 两侧逐行对账。原来界面上这一行连按钮都没有；只补按钮更糟，点下去必然
`sys.exit`。**理由必须写在行内**，不能用 `title` 悬停——悬停看不见等于没有。

判据在 `runs.stage_runnable()`：纯文件系统检查，不读大 JSON、不跑子进程
（`/api/state` 会对每本书调它），任何异常都降级成「不可运行 + 理由」。

### 4.4 校对 `#/task/:id/proofread` —— **核心，见第 5 节**

### 4.5 成品 `#/task/:id/output`

- 顶部：EPUB 文件名 + 大小 + 「下载 EPUB」主按钮。
- 四块统计卡：页数 / 汉字数 / 脚注（总数/已关联/孤立）/ 插图。
- 目录树（可折叠）：层级、标题、页码、匹配度。
- 质检问题列表：等级徽标 + 页码 + 说明。
- Markdown 预览：等宽、可折叠、只读，`max-height: 60vh` 内滚动。

### 5.2 证据图（硬指标）

- 容器高度 `clamp(420px, 58vh, 780px)`，**不小于 420px**。
- 默认「适应宽度」：切片图按容器宽度铺满；整页图按高度适配、居中。
- 缩放 4 档：100% / 150% / 200% / 300%，超出容器时容器内滚动、可拖拽平移。
- 两种模式：
  - **切片**（默认）：`GET .../crop?page=&y0=` 返回该行高分辨率裁图，
    上下留白 8px 已由后端加好。
  - **整页**：`GET .../page?page=` 整页图，用于「这句到底在哪」的上下文判断。
- 图片用 `image-rendering: auto`，不加滤镜不加边框，只用 `--border` 一圈细线。
- 加载中显示骨架条；加载失败显示「证据图不可用」+ 重试按钮，**不能白屏**。

### 5.3 候选与差异

- A / B 各一张 `--surface-2` 底的圆角块，`--fs` 字号，行高 1.7，字重 500。
- 差异用 `<mark>` 语义，但**不带任何底色**：

  | 操作 | 样式 |
  |---|---|
  | replace | 700 字重 + 2px 下划线，`text-underline-offset: 3px` |
  | insert | 700 字重 + 2px 下划线（新增的字在这一侧不存在，靠上下文读） |
  | delete | 700 字重 + 2px 删除线 |

  文字色沿用正文色（`inherit`），不加色相。

**为什么不用底色**（试过三套，包括 5.24:1 达标的浅琥珀 + 棕字）：

1. 底色在字周围铺一块色，形近字（已/己、己/已）的**笔画差别反而糊在色块边缘**，
   而那正是这个界面唯一要看清的东西。
2. 一行里出现两三处差异时，视线被色块牵走，真正要看的那两个笔画差别没人看。
3. 每多一种色相就多一句「这个颜色是什么意思」要解释；现在整行只有黑与灰两级。

底色只在**整块候选被选中**时出现在容器上（`--accent-soft` + `--accent` 边），
单个字只用字形本身说话。
- B 若来自 audit 词表建议，给 `--ok` 的「推荐」小徽标；否则不给，不要编造。
- 「自行输入」展开后可编辑文本框，预填当前选中候选的整行内容。

### 5.4 判定按钮（硬指标）

四个按钮，纵向排列，**整行宽度、高度 44px、字号 15px**：

| 按钮 | 样式 | 默认快捷键 |
|---|---|---|
| 采用 A | `--surface` 底 + `--border-strong` 边 | `A` |
| 采用 B | `--accent` 实心（主推） | `B` |
| 自行输入 | `--surface` 底 + 描边 | `C` |
| 跳过 | 文字按钮，`--fg-muted` | `S` |

判定后立即显示 200ms 的确认反馈（按钮短暂 `flash`），然后自动跳下一条。

**没做的**：`Shift+A/B/C/S` 反向撤销曾经写进规范，但没有实现——当前的
`judge()` 没有历史栈，硬写只会变成一个看着有、按了没反应的功能。
要么不做，要么真做；现在是不做。

### 5.5 分组侧栏

- 每项：分组名（`已→己` 用 `--mono`）+ 条数；选中项 `--accent-soft` 底 + 左 2px 强调条。
- 「未定位」单独一组置顶，用 `--warn` 图标，点开解释「这些建议在原页找不到对应行，
  必须人工补真实坐标」。
- 分组可一次「全组采用 B」，那是批量操作，必须二次确认弹窗。

### 5.6 进度与提交

- 顶部进度条：宽度 = 已校对 / 总数，填充 `--accent`。
- 「提交校对」右侧显示待提交条数徽标。**0 条时禁用**。
- 提交前弹预览：调 `POST .../apply/preview`，展示
  「将改动 N 处 / 已是目标值 M 处 / 找不到 K 处 / 忽略 J 处」四格 + 明细表前 20 行，
  底部「取消」与「确认回填并重建成书」。**没有预览就不能提交。**

### 5.7 键盘（可改绑）

键位**不是硬编码**，默认值如下，用户可在顶栏「设置」里逐项改：

| 默认键 | 动作 |
|---|---|
| `A` / `B` / `C` / `S` | 采用 A / 采用 B / 自行输入 / 跳过 |
| `↓` / `↑` | 下一条 / 上一条 |
| `Z` | 切换 整页 / 切片 |
| `1` / `2` / `3` / `4` | 缩放 100% / 150% / 200% / 300% |
| `/` | 聚焦分组过滤 |
| `Esc` | 关闭弹窗（**不可改绑**） |

**绑定纪律**：

- 一个动作一颗键、一颗键只给一个动作。所以原先 `↑↓` 与 `j/k` 的双绑被收掉了——
  双绑让「设置面板里当前生效的是哪颗」说不清，也没法改掉自己不想用的那颗。
- `Esc` / `Tab` / `Enter` 不开放绑定：分别是关弹窗、切焦点、误触当前按钮。
- 带 `Ctrl` / `Alt` / `Cmd` 的组合键一律不匹配，留给浏览器与系统。
- 改键交互是「点键帽 → 直接按新键」，不用下拉框：60 多个键名列出来还得自己找。
- 偏好存 `localStorage`（键 `bookflow.keys.v1`），存不下时**只降级不报错**
  （隐私模式下 storage 会抛异常，「存不住偏好」的代价远小于整页白屏）。

快捷键提示在按钮右侧以 `kbd` 样式小方块常驻显示，**显示的是当前生效的绑定**——
改完键之后按钮上还是旧的 `A`/`B`，等于界面对人说谎。

## 6. 交互纪律

- **所有失败都要可见**：接口错误弹出 `--danger` 的 toast，并在原位显示重试按钮。
  禁止静默失败、禁止把 404 兜成空列表。
- 加载态用骨架屏，不用转圈盖住整页。
- 破坏性操作（提交回填、中断执行、全组采纳）必须二次确认。
- 空态要说人话：例如「这本书还没有校对清单，先跑完审核阶段」。

截图由 `msedge --headless=new` 生成，是**真实渲染**（数据来自本地 `runs/` 里的四本书），
不是设计稿。重拍命令：

~~~powershell
& "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" `
  --headless=new --disable-gpu --hide-scrollbars `
  --user-data-dir="$env:TEMP\edge-shot" --window-size=1600,1000 `
  --virtual-time-budget=25000 `
  --screenshot="docs\ui\proofread.png" `
  "http://127.0.0.1:8913/index.html#/task/runs/hegel/proofread"
~~~

两个坑，都是**静默**的：

1. `--user-data-dir` 必须给。不给时若默认配置目录被别的 Edge 占用，截图会
   不报错、不产出文件，退出码也看不出问题——重试循环能拍到只是因为换了目录。
2. 拼 URL 时**别把 `#` 写两遍**。`"...index.html#$hash"` 里 `$hash` 本身已带 `#`，
   结果变成 `##/tasks`，`location.hash` 去掉一个 `#` 还剩 `#/tasks`，
   路由认不出就渲染「页面不存在」。本次五张图第一版全都是这么报废的。
   正确写法是 `"...index.html?v=123#/tasks"`（`?` 查询串在 `#` 之前是允许的）。

设置面板没法用 `--screenshot` 直接拍（要先点一下顶栏的「设置」按钮才弹出来），
所以留了一个只做这件事的 `webui/static/dev-settings-shot.html`。它不含业务逻辑，
不进产品流程。

## 7. 技术约束

- 原生 ES module，**无构建、无 npm、无 CDN**，离线可用。
- 样式拆成 `css/base.css`（令牌 + 共用组件）+ 每视图一份 `css/view-*.css`，
  令牌集中在 `base.css` 的 `:root`，视图文件只许引用令牌、不许写字面色值。
